## 1. 产品概述

### 1.1 产品定位

**Node 是一个纯 Web3 Native 的自管钱包与数字通行证管理中枢**。

它从原"IM开放服务生态矩阵"中独立剥离,聚焦于两件事:
1. **自管冷钱包**——用户链上资产的本地安全钥匙箱
2. **服务舱**——围绕钱包地址构建的福利、安全、身份服务

其他独立应用(包括拆分出去的 IM 聊天 App、DApp 浏览器、行业合作应用等)均通过"连接 Node"的方式,调用 Node 管理的冷钱包地址或本地 Web2 凭证进行去中心化签名登录。

### 1.2 产品边界

| 范畴 | 包含 | 不包含 |
|------|------|--------|
| **C 端 App** | 冷钱包舱 + 服务舱(福利特权/保险库/DID通行证) | IM 聊天通讯(已剥离为独立 App) |
| **B 端配套** | 服务管理后台(运营配置保险库/福利/合约/参数) | IM 开放服务统一后台(已剥离) |
| **身份体系** | Web3 钱包地址(主) + Web2 本地凭证(辅) | 平台托管钱包余额、云端账号体系 |
| **存储** | 本地 Keychain 加密存储 | 云端不存任何"地址↔Web2账号"映射 |

### 1.3 演变背景

Node 的前身是"IM开放服务生态矩阵"中的客户端层。演变历程:

```
阶段1 (2026-06): IM开放服务生态矩阵
  ├ IM App(聊天+发现页)
  ├ 福利特权中心(WebView嵌入)
  ├ 安全保险库(WebView嵌入)
  └ 冷钱包(WebView嵌入)

阶段2 (2026-07): 业务解耦,Node独立
  Node = 纯Web3自管钱包App
  ├ 冷钱包舱(资产看板/Swap/Faucet/收发)
  └ 服务舱
     ├ 福利特权中心(7模块)
     ├ 安全保险库(设备指纹钥匙+权益舱)
     └ 数字身份通行证(Web3钱包+Web2凭证)

阶段3 (未来): Node作为签名基础设施
  外部应用 → 连接Node → 签名登录 → 返回Proof
```

### 1.4 核心设计原则

1. **纯 Web3 Native 架构**:产品引导仅提供 Web3 自管钱包创建与导入,不设传统 Web2 注册/登录入口,不设云端托管个人中心。
2. **本地凭证存储,云端无状态**:Web2 凭证仅保存在本地 Keychain,云端和数据库绝不存储"钱包地址与 Web2 账号"的映射关系。
3. **地址即身份**:链上钱包地址是唯一真身,算钱/绑定/鉴权只信地址;短号、Web2 凭证仅作索引与登录辅助。
4. **数字身份连接器 (DID Provider)**:作为外部应用的"登录钥匙",第三方 App 拉起 Node 授权面板,用户选身份+输 PIN 码签名后完成登录。
5. **设备指纹硬约束**:保险库的设备指纹是绑定/领福利的前置闸门,一台物理设备同一时刻只能绑定一个钱包(反女巫)。

## 2. 产品架构总览

### 2.1 两大一级模块(C端 App)

Node App 由两个一级 Tab 构成,通过黑色悬浮胶囊底栏切换:

```
┌──────────────────────────────────────────────┐
│  Tab 1:冷钱包舱 (Wallet Panel)                │
│   ├ 资产看板(总估值/代币明细)                  │
│   ├ 收发控制(Swap/Faucet/发送/接收)           │
│   └ 钱包管理(创建/导入/注销/导出私钥)          │
├──────────────────────────────────────────────┤
│  Tab 2:服务舱 (Service Hub)                   │
│   ├ 福利特权(3模块)                           │
│   │   ├ 空投 / 资产 / 互动                     │
│   ├ 安全与保障                                │
│   │   ├ 保险库 (Vault)                        │
│   │   └ 数字身份通行证 (DID Pass)             │
│   └ DApp 探索                                │
└──────────────────────────────────────────────┘
```

### 2.2 B 端配套

```
服务管理后台
  ├ 服务注册中心(服务元数据驱动)
  ├ 产品服务配置(按产品隔离)
  ├ 合约与链配置
  ├ 业务参数配置
  ├ 用户权益与标签
  ├ 审计日志
  └ 权限管理(角色+产品二维)
```

### 2.3 身份与签名链路

```
外部App(IM App/DApp/合作应用)
  → 拉起Node授权面板(view-app-connect-modal)
  → 用户选择签名主体(Web3钱包地址 或 Web2本地凭证)
  → 输入6位本地PIN码
  → Node本地私钥签名Challenge(EIP-712)
  → 返回Signature Proof → 完成登录
```

## 3. 模块一:冷钱包舱 (Wallet Panel)

> 详细需求见 [PRD-冷钱包](./PRD-冷钱包.md),此处为总纲摘要。

### 3.1 定位

面向 C 端用户的链上资产管理入口。用户在此创建/导入自管钱包,查看资产、兑换代币、领取测试币、收发资产。

### 3.2 功能清单

| 子模块 | 功能 | 状态 | 优先级 |
|--------|------|------|--------|
| 资产看板 | 总估值 + 代币列表(RC/USDRs/HRCs/RSTs) | 原型完成 | P1 |
| Swap 兑换 | 自主链代币两两兑换 + 滑点控制 + 智能路由 | 原型完成,联调中 | P1 |
| Faucet 领取 | 每24h领5 RC,Gas不足平台代发(EIP-2771) | 原型完成,联调中 | P1 |
| 币种详情 | 余额 + 操作入口 + 价格走势 + 交易记录 | 原型完成 | P2 |
| 发送/接收 | 链上转账 | 占位 | P2 |
| 钱包管理 | 创建/导入/重命名/导出私钥/销毁注销 | 原型完成 | P1 |

### 3.3 代币体系

| 符号 | 名称 | 链 | 用途 |
|------|------|----|------|
| RC | RC Token | 自主链 | Gas 原生代币,Faucet 领取对象 |
| USDRs | USDR Stable | 自主链 | 平台主要代币,空投/返利币种 |
| HRCs | HRC Token | 自主链 | 生态联合 Token |
| RSTs | RST Token | 自主链 | 储备代币 |

### 3.4 关键技术方案

- **Swap**:自建 AMM 流动性池(恒定乘积公式),两代路由(直连 + USDRs 中转)
- **免 Gas Faucet**:EIP-2771 元交易 + Relayer 代付,兼容普通 EOA 钱包
- **滑点保护**:前端算 MinAmountOut + 合约级 `INSUFFICIENT_OUTPUT_AMOUNT` 校验

## 4. 模块二:服务舱 (Service Hub)

服务舱是围绕钱包地址构建的服务聚合页,包含福利特权、安全保障、DApp 探索三大区块。

### 4.1 福利特权

**定位**:C 端用户的权益领取与消费入口,围绕钱包地址提供空投、资产权益、互动激励等运营场景。

**3 个子模块**:

| 模块 | 功能 | 状态 |
|------|------|------|
| 空投 | 空投活动列表、详情、参与与领取 | 入口完成 |
| 资产 | 持仓返利、资产权益管理 | 规划中 |
| 互动 | 互动激励、任务参与 | 规划中 |

**入口形态**:服务舱内以"福利特权"大卡片呈现,含标题"福利特权"+副标题"空投·资产·互动",下方为 3 个等宽子卡片(空投/资产/互动),每个显示"0 待领"状态。

**多合约设计**:一个福利方案可对应多个奖励合约(跨链/分批发放),支持单个合约手动领取 + 一键领取全部。

**钱包绑定校验**:进入福利特权前检测钱包是否已绑定,未绑定则弹窗引导。

### 4.2 安全与保障

#### 4.2.1 保险库 (Vault)

> 详细需求见 [PRD-安全保险库](./PRD-安全保险库.md) / [服务设计方案](../03-方案/安全保险库服务设计方案.md) / [未来扩展架构](../03-方案/安全保险库未来扩展架构设计方案.md)。

**定位**:高安全等级资产托管与鉴权框架,核心解决女巫攻击(批量注册薅羊毛)。

**核心价值三要素**:
1. **物理级防刷**:一台物理设备同一时刻只能绑定一个钱包
2. **用户隐私合规**:设备 ID 本地哈希加密,不上传 IMEI/MAC 原始数据
3. **作弊成本倒逼**:已激活指纹解绑需付 500 USDT,使作弊成本远超收益

**两阶段生命周期**:

| 指纹状态 | 触发条件 | 链上状态 | 解绑规则 |
|----------|----------|----------|----------|
| 待激活 | 完成本地签名向导 | 本地存根(未上链) | 免费,无冷却 |
| 已激活 | 首次领福利成功 | 广播存证(已上链) | 付费 500 USDT |

**钥匙等级体系(三阶段演进)**:

| 等级 | 钥匙类型 | 状态 |
|------|----------|------|
| L1 | 设备指纹钥匙(当前) | 开发中 |
| L2 | 人脸/虹膜 + 硬件芯片钥匙 | 规划 |
| L3 | DNA 生物特征钥匙 | 远期规划 |

**保险柜服务舱矩阵(未来扩展)**:

| 服务舱 | 最低钥匙 | 业务场景 |
|--------|----------|----------|
| 虚拟权益舱(当前) | L1 | 积分、白名单、卡券 |
| 数字代币托管舱 | L2 | 稳定币、通证管理 |
| 实物交割与现金舱 | L3 | 法币代管、实物提取 |
| 永久性冷数据存储 | L2 | 遗嘱、社交恢复碎片 |
| 去中心化身份备份 | L2 | 根私钥碎片备份 |

#### 4.2.2 数字身份通行证 (DID Pass)

> 详细方案见 [Node独立自管钱包与数字通行证设计方案](../../原型/身份登录/Node独立自管钱包与数字通行证设计方案.md)。

**定位**:全屏管理子页面,由服务舱卡片拉起,提供多重身份的一站式管理。

**两层结构**:
1. **App 列表页(身份凭证中心)**:按应用维度展示已关联的数字身份概览
2. **App 身份管理页**:Tab 切换(Web3 钱包 / Web2 账号)+ 筛选(网络/类型)

**身份类型**:

| 类型 | 说明 | 存储位置 |
|------|------|----------|
| Web3 钱包 | 多链自管钱包地址 | 本地 Keychain + 链上 |
| Web2 账号 | 手机号/邮箱/系统账号 | 仅本地 Keychain |

**关键约束**:
- 云端和数据库**绝不存储**"钱包地址与 Web2 账号"的映射关系
- 断开 Web2 凭证为纯客户端操作,不涉及服务器交互
- Web3 钱包注入采用"网络选择 → 钱包选择 → 确认注入"三步流程

**外部 App 授权签名登录**:
```
第三方App发起挑战 → Node展示授权弹窗 → 用户选身份 → 输PIN码 →
本地私钥签名Challenge → 返回Signature Proof → 完成登录
```

### 4.3 DApp 探索

引导用户连接并访问 Web3 外部生态(当前占位,后续迭代)。

## 5. B 端配套:服务管理后台

> 详细方案见 [服务管理后台详细方案](../03-方案/服务管理后台详细方案.md)。

### 5.1 核心原则

| 原则 | 说明 |
|------|------|
| 服务独立于产品 | 服务在注册中心统一注册,各产品按需启用 |
| 配置按产品隔离 | 同一服务在不同产品中可配置不同参数 |
| 服务元数据驱动 | 服务代码声明任务定义和参数 Schema,后台同步渲染 |
| 中心化管理 | 一套后台统一管理,产品业务服务可分实例部署 |
| 全程可审计 | 配置变更、合约参数、发币、权益变更全部留痕 |

### 5.2 功能模块

1. **服务注册中心**:服务统一注册,各产品按需启用
2. **产品服务配置**:按产品隔离的服务参数配置
3. **合约与链配置**:合约地址、所属链、奖励币种管理
4. **业务参数配置**:Faucet 资金池、Swap 汇率、保险库解绑费等
5. **用户权益与标签**:用户钱包绑定状态、权益领取记录
6. **审计日志**:所有关键操作留痕
7. **权限管理**:角色 + 产品二维权限(部门维度暂不实现)
