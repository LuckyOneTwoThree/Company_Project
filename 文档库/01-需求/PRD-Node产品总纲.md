## 1. 产品概述

### 1.1 产品定位

**Node 是一个纯 Web3 Native 的自管钱包与数字通行证管理中枢**,围绕链上钱包地址构建"资产—关系—权益—身份—应用"五位一体的产品体系。

它从原"IM开放服务生态矩阵"中独立剥离,聚焦五件事:
1. **自管冷钱包**——用户链上资产的本地安全钥匙箱(资产)
2. **关系网络层**——基于链上地址的永久上下级绑定与多级返佣分账(关系)
3. **统一商品池**——级差返利商城 + 短号/流转资产处置(权益)
4. **应用分发**——第三方应用市场作为生态拓展入口(应用)
5. **服务舱**——围绕钱包地址构建的福利、安全、身份服务(身份)

其他独立应用(包括拆分出去的 IM 聊天 App、DApp 浏览器、行业合作应用等)均通过"连接 Node"的方式,调用 Node 管理的冷钱包地址或本地 Web2 凭证进行去中心化签名登录。

### 1.2 产品边界

| 范畴 | 包含 | 不包含 |
|------|------|--------|
| **C 端 App** | 5 Tab:钱包/团队/交易/应用中心/身份(详见 2.1 节顺序约定) | IM 聊天通讯(已剥离为独立 App) |
| **B 端配套** | 服务管理后台(运营配置保险库/福利/合约/参数) | IM 开放服务统一后台(已剥离) |
| **身份体系** | Web3 钱包地址(主) + Web2 本地凭证(辅) | 平台托管钱包余额、云端账号体系 |
| **存储** | 本地 Keychain 加密存储 + 链上关系存证 | 云端不存任何"地址↔Web2账号"映射 |

### 1.3 演变背景

Node 的前身是"IM开放服务生态矩阵"中的客户端层。演变历程:

```
阶段1 (2026-06): IM开放服务生态矩阵
  ├ IM App(聊天+发现页)
  ├ 福利特权中心(WebView嵌入)
  ├ 安全保险库(WebView嵌入)
  └ 冷钱包(WebView嵌入)

阶段2 (2026-07): 业务解耦,Node独立
  Node = 纯Web3自管钱包App
  ├ 冷钱包舱(资产看板/Swap/Faucet/收发)
  └ 服务舱
     ├ 福利特权中心(7模块)
     ├ 安全保险库(设备指纹钥匙+权益舱)
     └ 数字身份通行证(Web3钱包+Web2凭证)

阶段3 (2026-07 至今): Aeon R9 集成,5 Tab 架构成型
  Node 5 Tab 架构
  ├ Tab1 钱包(资产操作)
  ├ Tab2 团队(Aeon R9 关系网络落点)
  ├ Tab3 交易/商城(统一商品池+级差返利)
  ├ Tab4 应用中心(第三方应用分发)
  └ Tab5 身份(Web3身份的权益与凭证)

阶段4 (未来): Node作为签名基础设施
  外部应用 → 连接Node → 签名登录 → 返回Proof
```

### 1.4 核心设计原则

1. **纯 Web3 Native 架构**:产品引导仅提供 Web3 自管钱包创建与导入,不设传统 Web2 注册/登录入口,不设云端托管个人中心。
2. **本地凭证存储,云端无状态**:Web2 凭证仅保存在本地 Keychain,云端和数据库绝不存储"钱包地址与 Web2 账号"的映射关系。
3. **地址即身份**:链上钱包地址是唯一真身,算钱/绑定/鉴权只信地址;短号、Web2 凭证仅作索引与登录辅助。
4. **数字身份连接器 (DID Provider)**:作为外部应用的"登录钥匙",第三方 App 拉起 Node 授权面板,用户选身份+输 PIN 码签名后完成登录。
5. **设备指纹硬约束**:保险库的设备指纹是绑定/领福利的前置闸门,一台物理设备同一时刻只能绑定一个钱包(反女巫)。
6. **关系永久,迁移受限**:上下级关系 set-once,唯一可动关系的口子是 miner 多签 + 时间锁的治理迁移。
7. **多级返佣**:级差制返利模型,3 层上线分润,compression 动态压缩机制保证名额不浪费。
8. **统一商品池 + 级差返利**:全平台共享同一商品池、同一价格,购买触发沿上线链 N 层级差分润,等级决定返利比例。
9. **退货不退关系**:退货只退钱,不解除上下级绑定关系。

## 2. 产品架构总览

### 2.1 5 个一级 Tab (C 端 App)

Node App 由 5 个一级 Tab 构成,通过底部胶囊导航切换。**Tab 顺序约定**:钱包 → 团队 → 交易 → 应用中心 → 身份。

```
┌──────────────────────────────────────────────────────────┐
│  Tab 1: 钱包舱 (Wallet Panel) — 纯资产操作                │
│   ├ 资产看板(总估值/代币明细)                              │
│   ├ 收发控制(Swap/Faucet/发送/接收)                       │
│   └ 钱包管理(创建/导入/注销/导出私钥)                      │
├──────────────────────────────────────────────────────────┤
│  Tab 2: 团队 (Team) — Aeon R9 关系网络落点                │
│   ├ 推广中心(短号/二维码/邀请/团队申请)                    │
│   ├ 我的团队(上下级关系树)                                 │
│   ├ 邀请中心(定向邀请+状态机)                              │
│   ├ 佣金明细(L1/L2/L3分账+一键领取)                       │
│   └ 待分配池(仅代理/公司可见)                              │
├──────────────────────────────────────────────────────────┤
│  Tab 3: 交易/商城 (Mall) — 统一商品池 + 级差返利            │
│   ├ 官方统一商品池(全平台同价)                             │
│   ├ 直购下单(成交触发归因+级差返利)                        │
│   ├ 短号中心(短号资产化管理)                               │
│   ├ 流转市场(二手资产处置:一口价/拍卖/租赁/赠送)           │
│   ├ 订单管理(主辅分离4态+链下物流/卡密)                    │
│   └ 唯一码库存(0未设/1可售/2已售/3已退)                    │
├──────────────────────────────────────────────────────────┤
│  Tab 4: 应用中心 (App Market) — 第三方应用分发             │
│   ├ 官方精选(自家IM工具)                                   │
│   ├ IM社交 / 跨境电商 / Web3类                            │
│   ├ DApp 收录导航(即将开放)                                │
│   └ 我的(打开历史+上架申请)                                │
├──────────────────────────────────────────────────────────┤
│  Tab 5: 身份 (Identity Hub) — Web3 身份的权益与凭证        │
│   ├ 福利特权(空投/资产/互动)                              │
│   ├ 安全与保障                                             │
│   │   ├ 保险库(Vault,全App安全基座)                       │
│   │   └ 数字身份通行证(DID Pass)                          │
│   └ DApp 探索(占位)                                       │
└──────────────────────────────────────────────────────────┘
```

> **Tab 归属说明**(用户已拍板):
> - 短号中心、流转市场在 PRD 总纲中统一归 Tab 3 交易/商城,作为资产处置主入口
> - 福利特权、保险库、DID 通行证归 Tab 5 身份,保留原服务舱内容不删

### 2.2 B 端配套

```
服务管理后台
  ├ 服务注册中心(服务元数据驱动)
  ├ 产品服务配置(按产品隔离)
  ├ 合约与链配置
  ├ 业务参数配置
  ├ 用户权益与标签
  ├ 审计日志
  └ 权限管理(角色+产品二维)
```

### 2.3 身份与签名链路

```
外部App(IM App/DApp/合作应用)
  → 拉起Node授权面板(view-app-connect-modal)
  → 用户选择签名主体(Web3钱包地址 或 Web2本地凭证)
  → 输入6位本地PIN码
  → Node本地私钥签名Challenge(EIP-712)
  → 返回Signature Proof → 完成登录
```

## 3. 模块一:钱包舱(Tab 1)

> 详细需求见 [PRD-冷钱包](./PRD-冷钱包.md),此处为总纲摘要。

### 3.1 定位

面向 C 端用户的链上资产管理入口。用户在此创建/导入自管钱包,查看资产、兑换代币、领取测试币、收发资产。

### 3.2 功能清单

| 子模块 | 功能 | 状态 | 优先级 |
|--------|------|------|--------|
| 资产看板 | 总估值 + 代币列表(RC/USDRs/HRCs/RSTs) | 原型完成 | P1 |
| Swap 兑换 | 自主链代币两两兑换 + 滑点控制 + 智能路由 | 原型完成,联调中 | P1 |
| Faucet 领取 | 每24h领5 RC,Gas不足平台代发(EIP-2771) | 原型完成,联调中 | P1 |
| 币种详情 | 余额 + 操作入口 + 价格走势 + 交易记录 | 原型完成 | P2 |
| 发送/接收 | 链上转账 | 占位 | P2 |
| 钱包管理 | 创建/导入/重命名/导出私钥/销毁注销 | 原型完成 | P1 |

### 3.3 代币体系

| 符号 | 名称 | 链 | 用途 |
|------|------|----|------|
| RC | RC Token | 自主链 | Gas 原生代币,Faucet 领取对象 |
| USDRs | USDR Stable | 自主链 | 平台主要代币,空投/返利币种 |
| HRCs | HRC Token | 自主链 | 生态联合 Token |
| RSTs | RST Token | 自主链 | 储备代币 |

### 3.4 关键技术方案

- **Swap**:自建 AMM 流动性池(恒定乘积公式),两代路由(直连 + USDRs 中转)
- **免 Gas Faucet**:EIP-2771 元交易 + Relayer 代付,兼容普通 EOA 钱包
- **滑点保护**:前端算 MinAmountOut + 合约级 `INSUFFICIENT_OUTPUT_AMOUNT` 校验

## 4. 模块二:团队(Tab 2)

> 详细方案见 [Aeon R9集成Node产品架构演变方案](../03-方案/Aeon%20R9集成Node产品架构演变方案.md),此处为总纲摘要。

### 4.1 定位

Aeon R9 冷钱包上下级永久绑定方案的产品落点,核心是**基于链上地址的永久上下级关系绑定 + 5 渠道归因 + 多级佣金分账 + 治理迁移**。

**三铁律**(不可破坏):
1. **set-once**:上下级关系一次性写入,永久不可改
2. **退货不退关系**:退货只退钱,不解除绑定
3. **设备指纹校验**:绑定前必须通过 DeviceRegistry 校验

### 4.2 功能清单

| 子模块 | 功能 | 状态 | 优先级 |
|--------|------|------|--------|
| 推广中心 | 短号区两段式布局(上级/我的)+ 二维码/邀请/团队申请 | 规划中 | P1 |
| 我的团队 | 上级信息 + 直推下线(L1)+ 间接下线(L2/L3)+ 关系树 | 规划中 | P1 |
| 邀请中心 | 定向邀请 + 状态机(待接受/已接受/已过期,30 天窗口) | 规划中 | P2 |
| 佣金明细 | USDRs/RC/HRCs 可领取总额 + L1/L2/L3 分账明细 + 一键领取 | 规划中 | P1 |
| 待分配池 | 孤儿单认领(仅代理/公司可见,走 miner 审核) | 规划中 | P2 |

### 4.3 上级层级命名约定

- **LX** = 上上级(grandparent,离我更远的一级)
- **LY** = 上级(parent,我的直接上级)
- **链路格式**:`LX.LY`(如 `100000.100028`,上上级.直接上级)
- App 内只展示这两级,更深层级不在 App 内展示

### 4.4 返佣模型(级差制)

**等级 vs 层级**(严格区分,不可混淆):

| 维度 | 含义 | 范围 |
|------|------|------|
| 等级 rank | 横向:以自己为起点的"团队级别" | L1..L10 |
| 层级 layer | 纵向:单个订单里沿上线链的深度位 | +1/+2/+3 |

**派发规则**:每层返利按该层上线"自己的等级"取 `rebateBps[rank][layer]`,不受下游等级影响。

**返佣分账比例**:L1 20% / L2 14% / L3 10% + 7/6 + 2(待财务确认)。

**返佣时间期限(默认冻结期 7 天)**:

| 商品价格 | 冻结期 |
|----------|--------|
| 单价 < 500 USDT | 7 天 |
| 500 USDT ≤ 单价 < 2000 USDT | 14 天 |
| 单价 ≥ 2000 USDT | 30 天 |

### 4.5 5 渠道归因裁决优先级

| 优先级 | 信号 | 强度 | 场景 | 落点 |
|--------|------|------|------|------|
| 1 | 首次购买成交 | 最强(成交) | 买家已绑定则跳过,未绑定则绑卖家 | 商城→bindOnPurchase |
| 2 | 会话内显式扫码/接受邀请 | 强(当面/点对点) | 覆盖历史归因 | Tab 2 推广中心扫码 |
| 3 | 邀请链接/Deep Link | 中(窗口 30 天 last-touch) | 远程裂变 | Tab 2 邀请中心 |
| 4 | 无 | 无 | 进孤儿池 | 系统自动 bindOrphan |

### 4.6 治理迁移(唯一可动关系的口子)

```
proposeMigration(eta=+3天) → approveMigration(≥2 miner) → executeMigration(eta到期)
```

**三层防护**:
1. **多签**(2/2 miner)→ 防单点作恶
2. **时间锁**(3 天)→ 给社区异议窗口
3. **事件公示**(链上 MigrationProposed/Approved/Executed)→ 全程可审计

**下线自动跟随**:靠 `supersededBy[old] = new` + `resolve()` 重定向(8 次上限),无需逐个改下线关系。

**触发场景**:仅"丢私钥换地址",换机不影响(地址不变,走 DeviceRegistry 换绑设备)。

### 4.7 后端服务清单

| 服务 | 职责 | 优先级 |
|------|------|--------|
| **归因服务 Attribution** | 5 渠道信号汇聚 + 优先级裁决 | P2 |
| **邀请服务 Invitation** | pending 邀请表 + 状态机 + 30 天窗口 | P2 |
| **Relayer/Bridge** | 持 miner key 代提交 bindWithSig + 代付 gas | P2 |
| **Indexer** | 监听 Bound 事件 → closure table 落库 | P1 |
| **结算服务** | L1/L2/L3 佣金 + 年费分润 | P2 |

## 5. 模块三:交易/商城(Tab 3)

> 详细方案见 [Node商城模块设计方案](../03-方案/Node商城模块设计方案.md) / [流转市场产品设计方案](../03-方案/流转市场/01-流转市场产品设计方案.md) / [短号中心模块设计方案](../03-方案/短号中心模块设计方案（转移·赠送·可扩展交易）.md) / [交易 & 代理返利合约体系](../03-方案/交易相关合约/交易%20&%20代理返利合约体系.md),此处为总纲摘要。

### 5.1 定位

**统一商品池 + 级差返利** 的 Web3 商城:所有用户共享同一商品池,购买行为触发沿上线链 N 层级差分润,等级决定返利比例。同时承载短号中心与流转市场两类资产处置入口(用户已拍板)。

**三大核心决策**(对齐合约基准):

| 决策 | 含义 | 产品影响 |
|------|------|----------|
| **仅官方上架** | 矿工统一上架商品、统一定价、统一管库存 | 无 C 端商家入驻流程 |
| **全平台统一商品池** | 所有用户看到同一商品池、同一价格 | 无代理层级商品池概念 |
| **取消代销概念** | 无代销、无 Z 价、无上下级库存调拨 | 商品详情页仅"立即购买" |

### 5.2 用户角色

| 角色 | E 链绑定 | rank | 核心权限 | 入口限制 |
|------|----------|------|----------|----------|
| **游客** | ❌ 未绑定 | - | 浏览 + 购买(首次购买触发归因绑定) | 无代理中心 |
| **买家** | ✅ 已绑定 | 0 | 浏览 + 购买 + 订单 + 持有码 | 无代理中心 |
| **代理** | ✅ 已绑定 | 1..10 | 买家全部 + 代理中心 + 返利 + 升级 | 全功能 |

### 5.3 商品模型

| 类型 | pointsPerUnit | feedTeamPoints | secretCode | 典型场景 |
|------|---------------|----------------|------------|----------|
| **实物商品** | 0 | false | false | 硬件设备 |
| **虚拟商品** | 0 | false | true | 卡密/激活码 |
| **级别服务商品** | >0 | true | false | 升级服务包 |
| **积分商品** | >0 | false | false | 纯积分包 |

**商品定价规则**:
- **多币定价**:`price[productId][token]`,0 表示不接受该币
- **统一价**:全平台同价,不分代理层级
- **数量折扣阶梯**:`tiers[]=(minQty, bps)`,bps = 支付原价比例(7000=70%、6000=60%),取满足条件的最高 minQty 那档,默认 10000=原价

**保密商品(secretCode)**:商品级开关,开启后链上仅存哈希,**绝不上链明文卡密**,真实卡密由链下数据库管理,购买后用户凭订单 refId 调链下 API 领取。

### 5.4 唯一码库存模型

**状态机**:
```
0 未设 (unset) → 1 可售 (available) → 2 已售 (sold) → 3 已退 (returned)
```

**关键约束**:
- 500 库存 = 500 个唯一码
- 退货后状态变 3,**永久作废**(合约无重置方法)
- 已退码无法再次导入销售
- `productCodes` 视图仅返回可售码列表

### 5.5 级差返利体系

**两个维度**(核心):

| 维度 | 方向 | 范围 | 决定 |
|------|------|------|------|
| **等级 rank** | 横向(个人) | 0..10 | 返利比例 `rebateBps[rank][layer]` |
| **层级 layer** | 纵向(订单) | 1..rebateLayers | 分润深度位 |

**返利矩阵示例**(rank × layer):

| rank | L1 返利 | L2 返利 | L3 返利 |
|------|---------|---------|---------|
| 1 | 15.0% | 8.0% | 2.0% |
| 5 | 19.0% | 10.0% | 3.0% |
| 10 | 25.0% | 13.0% | 5.0% |

**动态压缩(compression)**:
- **开**(默认):某层上线 `level=0`(未达标/未激活)→ 跳过,名额上卷给上面下一个合格上线
- **关**:该层作废(浪费一个名额)
- `maxCompressionSkips = 20`(默认,硬上限 100,防 gas 爆炸)

|--------|----------|----------|
| `created` | exists=true, returned=false, 无 open ReturnReq | 否 |
| `return_requested` | exists=true, returned=false, 有 open ReturnReq | 否 |
| `returned` | returned=true | **是,不可逆** |
| `return_rejected` | exists=true, returned=false, 有已关闭 ReturnReq 且非 approved | 否(可再申请) |

### 5.10 退货流程关键约束

- **"已领奖励必须先退回"是业务流程要求,非合约硬条件**:合约层 `approveReturn` 不校验,依赖 miner 审核责任
- **approveReturn 隐藏行为**:`r.open = false` 和 `o.returned = true` 在 `revokeOrder` 之前设置,即使 revokeOrder 失败也标记为已退
- **关系不变**:E 链 referrerOf 永久,退货不退关系
- **码状态变 3**:退货后永久作废,合约无重置方法,无法再次 importCodes
- **refundAmount 由 miner 决定**:合约不校验金额合理性,可以是 0、部分、全额、超额,矿工责任重大
- **部分退货的严重限制**:合约层 `returnRequest` 只支持单码退货,且 `approveReturn` 后整个订单标记为 `returned=true`,后续其他码无法再申请退货。推荐方案 A:整单退 + 重新买剩余

### 5.11 C 端设计原则

1. **极简主义**:商品详情页底部按钮仅"立即购买",无代销/无 Z 价/无上下级商品池概念
2. **角色信息隐藏**:C 端不展示"购买者视角/上级分佣"等内容
3. **浅色主题**:全平台浅色主题,信息密度优先于视觉装饰
4. **渐进式引导**:游客可浏览可购买(降低参与门槛),首次购买触发归因绑定(无感知),代理功能仅在已绑定 rank≥1 时显示

### 8.2 功能模块

6. **审计日志**:所有关键操作留痕
7. **权限管理**:角色 + 产品二维权限(部门维度暂不实现)
