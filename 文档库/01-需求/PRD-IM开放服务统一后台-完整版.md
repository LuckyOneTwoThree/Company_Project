# IM 开放服务 — 统一后台管理产品需求文档（PRD）

> 版本：v1.0  
> 日期：2026-05-22  
> 状态：终稿

---

## 一、项目背景与目标

### 1.1 背景

公司有多款 IM 工具，内设"开放服务"入口（类似微信余额下方的服务列表），用户可进入会员、空投、商城等服务。当前有三个 IM 产品（A/B/C），分别独立部署，用户体系和业务数据均按产品隔离。

### 1.2 目标

建立一套**统一后台管理系统**，支持：

- **服务治理**：服务注册中心，开发一次三产品复用
- **产品配置**：按产品维度配置服务、链、合约、业务参数
- **多产品代理**：运营组织可同时代理多个产品，通过产品切换进行配置
- **权限管控**：超级管理员可创建下级账号，分配不同角色和产品权限
- **审计追踪**：所有关键操作留痕，支持追溯

### 1.3 核心原则

| 原则 | 说明 |
|------|------|
| 服务独立于产品 | 服务在注册中心统一注册，各产品按需启用 |
| 配置按产品隔离 | 同一服务在不同产品中可配置不同参数，链与产品绑定 |
| 用户按产品隔离 | 三个 IM 产品的用户、钱包、权益、订单和领取记录互不共享 |
| 多产品代理 | 一个运营账号可同时代理多个产品，通过产品切换操作 |
| 统一入口 | 一套后台 + 权限划分，不同角色看到不同菜单和数据 |
| 所有关键操作可审计 | 配置变更、合约参数、发币、权益变更全部留痕 |

## 二、用户角色与权限模型

### 2.1 角色定义

| 角色 | 说明 | 可管理产品 |
|------|------|-----------|
| **超级管理员** | 开发总部人员，拥有全部权限 | 全部产品（A/B/C） |
| **产品运营** | 运营组织人员，负责具体产品运营 | 被授权的产品（如 A+C） |
| **财务** | 负责合约配置、发币记录 | 被授权的产品 |
| **审计员** | 仅查看审计日志 | 全部 |

### 2.2 权限矩阵

| 功能模块 | 超级管理员 | 产品运营 | 财务 | 审计员 |
|----------|-----------|----------|------|--------|
| 服务注册中心 | 读写 | 只读 | - | - |
| 产品服务配置 | 读写 | 读写 | - | - |
| 合约与链配置 | 读写 | - | 读写 | - |
| 业务参数配置 | 读写 | 读写 | - | - |
| 用户权益管理 | 读写 | 只读 | - | - |
| 运营报表 | 读写 | 只读 | - | - |
| 审计日志 | 只读 | - | 只读 | 只读 |
| **权限管理（创建下级账号）** | **读写** | **-** | **-** | **-** |

### 2.3 权限粒度

后台权限采用“资源 + 动作”的细粒度权限点，角色只是权限点集合，避免仅用 `global / operate / config / audit` 这类粗粒度标识导致越权。

| 权限点 | 说明 | 默认角色 |
|--------|------|----------|
| service:read | 查看服务注册中心 | 超级管理员、产品运营 |
| service:write | 注册、编辑、启停全局服务 | 超级管理员 |
| product_service:read | 查看产品服务配置 | 超级管理员、产品运营 |
| product_service:write | 启用、停用、排序、编辑产品服务 | 超级管理员、产品运营 |
| chain:read | 查看链与合约配置 | 超级管理员、财务 |
| chain:write | 编辑链、合约、平台钱包配置 | 超级管理员、财务 |
| biz_param:read | 查看业务参数 | 超级管理员、产品运营 |
| biz_param:write | 编辑会员、空投、商城业务参数 | 超级管理员、产品运营 |
| entitlement:read | 查看用户权益 | 超级管理员、产品运营 |
| entitlement:write | 手动添加、移除、变更用户权益 | 超级管理员 |
| report:read | 查看运营报表 | 超级管理员、产品运营 |
| audit:read | 查看审计日志 | 超级管理员、财务、审计员 |
| system:read | 查看系统实例、网关、缓存、定时任务配置 | 超级管理员 |
| system:write | 编辑系统实例、网关、缓存、定时任务配置 | 超级管理员 |
| permission:write | 创建、编辑、停用账号和角色授权 | 超级管理员 |

### 2.4 账号管理

- 超级管理员可在后台创建下级账号
- 创建时可指定：用户名、密码、角色、可管理的产品列表
- 支持启用/停用/重置密码/删除账号
- 账号列表展示：用户名、角色、产品权限、状态、最后登录时间

## 三、产品维度与数据隔离

### 3.1 核心概念：产品作为配置容器

```
产品 A（企业即时通讯）
  ├─ 已启用服务：会员、空投、商城
  ├─ 已配置链：链X、链Y
  ├─ 合约配置：代币合约、空投合约
  ├─ 业务参数：会员价格、空投活动、商品信息
  └─ 运营数据：用户统计、订单数据、领取记录

产品 B（社交聊天工具）
  ├─ 已启用服务：会员、商城
  ├─ 已配置链：链Z
  └─ ...
```

### 3.2 产品切换机制

- 运营视角页面（数据概览、会员、空投、商城、配置等）**顶部显示产品切换栏**
- 切换产品后，页面数据自动刷新为当前产品数据
- 全局视图（服务管理、链合约管理、产品管理、系统配置、审计日志）**不受产品切换影响**

### 3.3 数据隔离规则

| 数据类型 | 隔离方式 | 说明 |
|----------|---------|------|
| 产品服务配置 | 按 product_id 隔离 | 每个产品独立配置启用哪些服务 |
| 链合约配置 | 按 product_id 隔离 | 链与产品绑定 |
| 业务参数 | 按 product_id 隔离 | 会员/空投/商城参数按产品独立 |
| 运营报表 | 按 product_id 隔离 | 用户统计、订单数据按产品分离 |
| 用户权益 | 按 product_id 隔离 | 用户、钱包、会员、订单、空投领取记录均属于具体产品 |
| 服务注册 | 全局共享 | 服务池所有产品共用 |

## 四、功能模块详细设计

### 4.1 模块一：服务注册中心

#### 功能说明

所有开放服务在此统一注册。新增服务只需注册，各产品按需启用。

#### 功能清单

| 功能 | 说明 |
|------|------|
| 注册新服务 | 填写完整服务参数（见下方） |
| 编辑服务信息 | 修改服务名称、描述、图标等 |
| 启用/停用服务 | 全局开关 |
| 查看服务列表 | 查看所有已注册服务及其状态 |
| 查看服务被哪些产品启用 | 查看服务的使用情况 |

#### 服务注册完整参数

| 参数类别 | 参数 | 说明 |
|----------|------|------|
| 基本信息 | 服务名称、服务Key、描述、图标、入口URL | 服务标识信息 |
| 链绑定 | 链绑定模式（不需要/可选/必须）、支持的链（多选） | 服务与链的关系 |
| 合约绑定 | 需要的合约类型（多选：token/airdrop/membership/nft/staking） | 启用时需配置的合约 |
| 触发模式 | 主动触发/被动触发/混合模式 | 用户操作 vs 系统定时 |
| 服务元数据 | 服务任务定义、业务参数Schema、任务参数Schema | 由服务开发侧声明或同步，后台只读取和展示 |
| 前置条件 | 需要登录、需要绑定钱包 | 进入服务的门槛 |
| 依赖服务 | 依赖其他服务（多选） | 启用前需先启用的服务 |
| 回调通知 | 事件回调URL、通知方式 | 服务事件通知机制 |
| 限流配置 | 接口限流（如 100/min） | API 频率限制 |
| 数据作用域 | 按产品隔离 / 全局共享 | 数据隔离方式 |

> 服务对应的定时任务和参数字段不是运营在注册服务时临时创建的，而是服务开发时随服务代码声明。后台通过服务元数据接口或发布流程同步这些定义，用于渲染配置表单、校验配置值和展示任务能力。

### 4.2 模块二：产品服务配置

#### 功能说明

为每个 IM 产品配置启用哪些服务，以及各服务的展示方式和交互规则。

#### 功能清单

| 功能 | 说明 |
|------|------|
| 切换产品维度 | 顶部切换当前操作的产品（A/B/C） |
| 启用服务 | 从服务注册中心选择服务，启用到当前产品 |
| 停用服务 | 停用当前产品的某个服务 |
| 配置展示名称 | 自定义服务在当前产品的展示名称 |
| 配置图标 | 自定义服务在当前产品的图标 |
| 配置入口URL | 自定义服务在当前产品的静态入口地址 |
| 配置排序 | 拖拽或输入排序值 |
| 配置是否需要登录 | 进入该服务是否需要登录态 |
| 配置是否需要钱包 | 进入该服务是否需要绑定钱包 |
| 配置业务参数 | 根据服务元数据中的业务参数Schema填写当前产品的实际值 |
| 配置定时任务 | 根据服务元数据中的任务定义配置当前产品的启停、cron、时区、执行参数和重试策略 |

#### 服务元数据与产品配置边界

| 层级 | 负责内容 | 是否可由运营新增 |
|------|----------|------------------|
| 服务代码/服务元数据 | 服务有哪些业务参数、任务、任务参数、字段类型、默认值、校验规则 | 否 |
| 后台管理系统 | 同步服务元数据，渲染表单，校验输入，保存产品配置值 | 否 |
| 产品服务配置 | 当前产品对这些参数和任务的具体取值、启停和运行策略 | 是，仅限填写和调整已有字段 |

### 4.5 模块五：用户权益与标签

用户权益与标签按产品隔离。后台查询、添加、移除权益时必须先确定当前产品，`user_id` 只在当前产品用户体系内有效，不跨产品复用。领取记录按产品隔离，每条记录包含 category 字段用于分类筛选（airdrop/rebate/ecology/vip/referral）。

#### 标签体系

| 标签类型 | 标签值 | 来源 |

| hardware_buyer | active / refunded / revoked | 商城订单支付后自动写入 |
| airdrop_claimed | campaign_id | 空投领取后自动写入 |
| risk_limited | limited / normal | 风控系统写入 |

#### 功能清单

| 功能 | 说明 |
|------|------|
| 查询用户权益 | 按产品 + 用户ID查询当前产品内的权益标签 |
| 手动添加标签 | 运营手动为用户添加标签 |
| 手动移除标签 | 运营手动移除用户标签 |
| 标签类型管理 | 管理可用的标签类型 |
| 权益变更记录 | 查看用户权益变更历史 |

## 五、客户端配置读取流程

### 5.1 IM客户端获取服务列表

```
IM客户端 → Nginx网关 → 开放服务API → Redis缓存/业务库 → 返回服务列表
```

客户端读取服务列表使用正式开放接口，不复用后台管理接口。

| 接口 | 说明 |
|------|------|
| GET /api/client/products/{productId}/services | 获取指定产品已启用、已排序的开放服务列表 |
| GET /api/client/products/{productId}/services/{serviceKey}/config | 获取指定服务的展示配置、入口URL、前置条件和必要业务参数 |

### 5.2 静态服务页面获取业务数据

```
静态服务页面 → 产品业务服务 → 当前产品用户库 + 当前产品业务库 → 返回身份+权益+业务数据
```

## 六、技术架构

### 6.1 部署架构

- 管理后台采用中心化部署：一套管理前端 + 一套管理API，统一管理服务注册、产品配置、权限和审计
- 产品业务服务可按 A/B/C 分实例部署，分别连接各自的用户库和业务库
- 管理库只保存后台账号、角色权限、服务注册、服务元数据、产品配置和审计日志，不承载 IM 终端用户体系
- Nginx/API网关统一透传 `X-Product-Id`，管理API和业务API均以该 Header 作为当前产品上下文
- Redis 共享，用于配置缓存、会话、限流和异步任务状态
- 链节点、平台钱包、合约配置按产品隔离，管理API统一配置后分发给对应产品业务服务

### 6.2 技术选型

| 层级 | 技术 | 说明 |
|------|------|------|
| 前端 | React / Vue + Ant Design | 管理后台常规选型 |
| 网关 | Nginx + JWT认证 | 反向代理 + Token校验 |
| 服务端 | Node.js / Go / Java | 依据团队技术栈选择 |
| 数据库 | PostgreSQL / MySQL | 关系型，支持JSON字段 |
| 缓存 | Redis | 配置缓存、会话管理 |
| 链上交互 | ethers.js / web3.js | 合约调用、交易签名 |
| 消息队列 | Redis / RabbitMQ | 异步任务（发币、快照） |
| 定时任务 | node-cron / Celery | 持仓快照、活动状态切换 |

| 阶段 | 模块 | 说明 |
|------|------|------|
