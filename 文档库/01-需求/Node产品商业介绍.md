## 一、一句话介绍

Node 是一个纯自管的 Web3 钱包，也是一个以链上地址为唯一身份的商业平台。它把原本分散在不同应用里的五件事——资产、推荐关系、商品交易、应用分发、数字身份——第一次装进同一个链上地址，并用智能合约保证其中的关系与分配不可篡改。

对用户而言，Node 是一个可以存资产、买商品、带团队、领佣金、转手资产的 App。对合作方而言，它是一条自带链上身份与支付能力的分销与分发渠道。对外部伙伴而言，它的收入不依赖代币发行，而来自真实商品成交、资产发行与流转手续费、以及应用分发抽成。

## 二、我们要解决的问题

Web3 钱包赛道已经很拥挤，但绝大多数产品只解决了「把币存起来」这一件事。当它们试图往商业化走，三个问题会同时暴露。

**第一，资产自管的安全假设是失衡的。** 用户弄丢私钥就一无所有，平台无能为力；反过来，一个人用一台设备批量注册几十个账号、把平台的新手激励和空投薅空，平台同样无能为力。安全不只是防黑客，还得防女巫。

**第二，推荐关系不可信。** 传统分销体系里，关系存在中心化数据库中，可以被后台修改；归因规则不透明，渠道冲突时说不清到底算谁的；佣金能不能拿到取决于平台意愿。结果是真正有能力带团队的人不敢真投入。

**第三，链上权益没有流通市场。** 短号、卡密、服务包、商品提货码，这些东西在各家平台都是孤岛式存在，买到手里要么自己用完，要么就砸在手里。没有二手市场就没有退出通道；没有退出通道，用户买第二件的意愿就很低。

这三个问题分别对应**安全、信任、流动性**。Node 的产品结构就是围绕这三个词设计的。

## 三、产品全景

Node 由五个模块组成：钱包、团队、交易、应用中心、身份。它们不是五个并列的功能集合，而是一条有先后依赖关系的链。

**钱包**是资产的家，提供资产看板、代币兑换、链上转账和零成本的 Gas 获取。它是整个产品的入口，也是唯一不需要任何前置条件就能用的模块。

**团队**是关系的账本，记录谁绑了谁、每笔成交的佣金往上走三层分给谁。这一层的全部数据都在链上，写入后不可修改。

**交易**是钱的引擎，包含官方统一商品池、短号发行中心，以及一个二级流转市场。平台绝大多数收入发生在这一层。

**应用中心**是流量的出口，把钱包的链上用户开放给第三方应用，平台按分发、推广、交易三条线抽成。

**身份**是信任的底座，包含福利特权、安全保险库和数字身份通行证。它不直接赚钱，但前四个模块能不能成立，取决于它。

五个模块串起来是一条完整闭环：用户在钱包里持有资产 → 在团队里确定不可变的推荐关系 → 在交易完成成交并触发多级分润 → 买到的资产可以进二级市场重新定价 → 应用中心与身份把这个闭环的价值向外放大。

在展开各模块之前，有三条贯穿全产品的原则需要先说清楚，因为后面很多设计选择都是它们的直接结果：

1. **私钥永不上链、永不上云。** 私钥本地加密存储，平台没有任何技术手段代用户动用资产。
2. **关系永久，且只能随地址迁移。** 上下级关系一旦链上写入就不可修改，任何人包括平台都改不了。
3. **地址即身份。** 所有权益、等级、分润均以钱包地址为唯一锚定依据，不以手机号或账号为准。

## 四、钱包：从存储到流通

### 4.1 基础能力

钱包提供完整的自管闭环：创建、导入、导出私钥、销毁钱包；资产看板展示总估值与多币明细（RC、USDRs、HRCs、RSTs）；支持链上收发转账，寻址时既可用完整地址也可用短号。

### 4.2 钱包地址与短号的关系

这是理解 Node 整个设计的关键，也是最容易被误解的一点。

钱包地址（形如 `0x71C7...98A5`）是**链上唯一真身**，不可修改，所有的算钱、绑定、鉴权只认它。短号（形如 `#100068`）是**地址的易记别名**，同时它本身也是一个可交易的链上资产。

两者的分工是：地址负责安全，短号负责传播。一个地址可以绑定多个短号，但同一时间只有一个被设为「展示短号」对外露出。因为短号是资产而不是账号，所以它可以卖、可以送、可以租。

这带来一个很重要的结果：**卖掉短号不等于卖掉团队。** 上下级关系、积分、等级全部绑定在地址上，短号转手只是别名易主，买家不会因此继承卖家的团队。同样的道理，用户换手机、重装 App、导入同一个私钥，地址没变，关系与积分就完全不变。

### 4.3 水龙头：从平台发钱到社区任务市场

新用户面临的第一个障碍是没有 Gas 币。目前已上线的基础水龙头允许每 24 小时领取 5 RC，平台代付 Gas，总池 5 万 RC，并通过设备指纹排他、IP 频次限制、防重放三重机制防刷。

正在开发的社区层把它升级为一个双向任务市场：平台或高级代理（等级 rank ≥ 3）可以发布任务并锁定预算（代理需押金 50 USDT 等值），用户在任务大厅接单，完成后自动发奖。首期只上链上可验证的任务，比如邀请绑定、首次兑换、绑定短号、激活保险库；链下任务待防作弊方案成熟后再开。

这一改造的商业意义在于：获客成本从平台单方承担，变成代理自己出钱买增长，平台只提供轨道和发奖保障。

### 4.4 Swap 与分级白名单

兑换分为两个层次。两条主通道完全开放、零门槛：`RC ↔ USDRs` 是站内基础兑换，`USDT ↔ USDRs` 是外部入金主通道。这保证新用户不会在第一步就被卡住。

涉及生态代币与大额交易时，才启用白名单：

| 场景 | 门槛 |
|-|-|
| HRCs 相关兑换 | 团队等级 rank ≥ 3 |
| 单笔 ≥ 1000 USDT 等值 | rank ≥ 5 或 持仓 ≥ 5000 USDRs |
| 单笔 ≥ 10000 USDT 等值 | rank ≥ 7 或 持仓 ≥ 20000 USDRs |

这里的设计选择值得展开：白名单的判定依据不是 KYC，而是**团队等级或持仓量**，且两者是「或」的关系。对一个自管钱包而言，强制 KYC 会直接摧毁它的产品定位；而等级与持仓都是链上可验证的长期行为证据，同样能起到风控作用。这也是钱包与团队体系的第一个耦合点。

## 五、团队：不可篡改的关系账本

### 5.1 基础能力与硬前置

团队模块包含四部分：推广中心（展示短号、生成二维码、发邀请、处理团队申请）、我的团队（关系树、等级与积分进度、升级申请）、邀请中心（30 天有效的定向邀请与完整状态机）、佣金明细（三层分账、多币可领、一键领取）。

所有团队能力都有一个硬前置：**必须先完成设备指纹绑定**。一台物理设备同一时刻只能绑定一个钱包，完整的逻辑链条是「设备指纹 → 团队绑定 → 交易购买」，三环不可跳过。这是整个反女巫体系的地基，也是平台敢持续发放福利与空投的前提。

### 5.2 归因：五个渠道与优先级

用户成为下级有五种路径，当多个渠道同时命中时，按以下优先级裁决（高到低）：

1. **扫码** —— 扫描上级的二维码，意图最强
2. **搜索短号** —— 主动搜索并申请绑定
3. **邀请链接** —— 30 天 last-touch 归因
4. **团队申请** —— 待上级审批
5. **孤儿池** —— 没有任何推荐人时系统自动分配

规则公开且上链，任何一方都可以自行验证归因结果，不需要信任平台客服的裁定。

### 5.3 返佣：级差与压缩

一笔成交会沿上线链向上取 **3 层**，每一层按**该层上线自己的等级**取返利比例。这里有两个容易混淆的概念必须分开：**等级（rank）**是个人职级，L1 到 L10，由自己的业绩与积分决定；**层级（layer）**是在某笔具体订单中所处的位置。返佣比例由 rank 决定，位置由 layer 决定。

当某一层上线等级完全不达标（rank = 0）时，系统会**动态压缩**：自动跳过这个人，把他的份额上卷给下一个合格的上线。总名额恒定为三层，名额不会因为有人不达标而浪费。

### 5.4 返佣时序与冻结期

返佣不是成交即到账。完整时序是：成交时佣金分配到上线名下但处于冻结状态 → 用户确认收货 → 冻结期开始倒计时 → 期满才可领取。

冻结期长度按商品单价分档：低于 500 USDT 为 7 天，500 到 2000 USDT 为 14 天，2000 USDT 以上为 30 天。

这层时间闸门是必需的。没有它，「买货 → 领佣 → 退货」就是一个无限套利循环。退货发生时的处理规则有三条：退货只退钱，**不解除上下级关系**；未领佣金自动撤销；已领佣金**从其后续未领佣金中自动抵扣**，抵扣完成前不可发起新的领取。整个过程由合约执行，不依赖人工追回。

### 5.5 烧断机制（机制待评审）

动态压缩只处理了「上线完全不达标」这一种情况。还有一种更隐蔽的不合理：**上层等级低于下层**。弱上级虽然达标，但仅凭位置就吃掉了强下级应得的份额，实际做事的推广者反而拿得少。

拟定的处理思路是：当某层上线等级低于本层应得门槛时触发烧断，份额沿链上卷至最近的等级满足要求的上线；如果整条链上都找不到合格上线，则转为积分补偿给实际推广者，或计入平台风险池。

**本机制为设计方向**，具体规则以正式版本为准：判定基准取「层级门槛」还是「与下层 rank 相比」；烧断掉的份额是否补偿实际推广者，补现金还是补积分；是否设烧断层数上限。本文描述不构成最终规则承诺。

但设计立场是明确的：返佣应归属于真正干活且够格的人，不允许位置吃掉能力。

### 5.6 积分与资产的转移规则

Node 里有四类东西可能被转移，规则各不相同：

| 对象 | 可否转移 | 说明 |
|-|-|-|
| 短号 | 可以 | 转移 / 赠送 / 挂售 / 拍卖 / 出租，即时链上过户 |
| 团队积分 | 可以 | 高级代理可按百分比自行设定转给重点下级 |
| 个人积分 | 不可 | 防止直接「买等级」 |
| 上下级关系 | 不可 | 永久不可改，仅能随地址整体迁移 |

团队积分转移是一个已上线能力，目的是让团队长能把资源定向投到重点下级身上。为了防止它退化成积分买卖，设了三道约束：单次转出不超过持有量的 30%，单月累计不超过 50%；转入的积分**不可用于升级**，仅可用于消耗等级权益；每笔转移经 PIN 签名并上链留痕，双方可查。

## 六、交易：收入的主体

### 6.1 统一商品池

传统分级分销体系里，各级代理自己上架、自己定价、自己囤库存，结果是同一件商品在平台上有十几个价，价格体系崩溃、用户体验割裂。

Node 采用统一商品池：**仅官方上架，全平台同一价，官方统一管库存**，所有用户看到的是同一份商品列表。代理的价值不再体现在「控货控价」上，而回归到推广本身。

商品分四类：实物商品（需物流）、虚拟商品（卡密类，保密品链上只存哈希）、级别服务商品（累加团队积分）、积分商品（即时发放）。

库存的最小单位是**唯一码**，状态从「未设」到「可售」到「已售」，退货后进入「已退」并永久作废。它在用户手里叫「持有码」，进二级市场后叫「商品码」，本质是同一个东西。

退货流程由矿工审核，且**先校验佣金退回状态再放款**，避开了「退款已出、佣金要不回来」的坑。

### 6.2 交易身份由团队决定

未绑定团队的游客可以自由浏览全部商品和价格，但**不能下单**。下单必须先完成团队绑定。

这一限制的目的不是逼用户拉人，而是保证每一笔成交都有一条清晰、不可篡改的归因链路。否则佣金就算不清，而佣金算不清是分销体系崩塌的头号原因。

### 6.3 短号中心：一条自有收入线

短号中心分三部分：我的短号（管理已绑定短号、设定展示短号、转移与赠送）、购买靓号（按 5 到 8 位筛选）、免费号（随机 10 个 10 到 12 位候选，每身份仅领一次）。

靓号定价模型很简单：5 位基价 1000 USDT 等值，每多一位乘 0.9（越短越贵）；在此基础上叠号型加成——豹子 ×50、顺子 ×20、四连同 ×10、葫芦 ×8、双对 ×5、吉尾 ×3。

靓号是几乎纯毛利的自有收入，而且它不是一次性的——发行后它会自然流入二级市场，每次转手都可能产生手续费。

### 6.4 二级市场（重点）

二级市场是 Node 与普通分销商城最本质的区别，也是目前能力最丰富的模块。它的定位是用户名下所有链上资产的**二手处置中心**。

**一条铁律先说在前面**：二级市场的所有渠道流水**一律不进级差返利**。它是资产处置而不是团队裂变，也因此**不强制要求团队绑定**。一级发行归交易，二次处置归流转市场，两边账不混。

**四个交易渠道**（二级市场整体开发中，以下为完整设计）

| 渠道 | 适用场景 | 手续费 | 机制要点 |
|-|-|-|-|
| 一口价 | 主渠道，快速变现 | 0% | 卖家定价即锁定资产，货款全额归卖家 |
| 拍卖 | 高价靓号、限量资产 | 2.5% | 设起拍价、加价幅度、时长；出价即锁资金，最高价者得 |
| 租赁 | 使用权与所有权分离 | 按协议定稿 | 基于 ERC-4907，支持独占与非独占两种模式 |
| 赠送 | 定向过户 | 号主付费，按协议定稿 | 不进挂单列表，即时过户 |

一口价手续费定为 0% 是刻意的引流设计——先把流动性做起来，手续费在拍卖和租赁上收。

**六类可流转资产**：靓号短号、免费号短号、实物商品码、虚拟兑换码、服务包码、保密商品码（链下脱敏，链上只露哈希）。

**完整能力**。一口价支持挂单、购买、撤单，以及矿工强制撤单。拍卖支持挂拍、出价（资金锁定）、成交，以及强制结算、强制取消、退款提取三个兜底动作。租赁支持出租（设租金、租期、独占开关）、承租、结束租赁——出租方与矿工可以提前终止，租客只能到期结束；非独占模式下资产可以同时挂售，但必须向租客明示。赠送由号主付费即时过户，订单中心留痕。

**谁能挂、谁不能挂**。已绑定的短号和已发放到用户的商品码四渠道全开；转移中或已挂售的短号有跨渠道锁，不能重复挂；平台在库尚未发放的商品码不可流转；已退货的码永久作废。

**六道风控**：跨渠道锁防双挂、矿工强制撤单防恶意挂单、拍卖三件套防交易卡死、保密品链下脱敏防卡密泄露、已退码永久作废防二次流转、短号跨网络流转在合约层拦截。

规划中还有荷兰拍（线性降价，适合清仓）与集邮挖矿两个渠道，优先级较低。碎片化流转因合规风险过高，**明确不启动**。

### 6.5 交易与团队的联动：代理能力商品

交易里有三类商品会直接作用于团队模块：**代理能力商品购买后获得发展下级的白名单权限（可发起二维码、邀请、团队申请）；级别服务商品累加团队积分，是 L3 以上升级的燃料；个人积分商品**累加个人积分，是 L1 到 L2 升级的燃料。

设计目的是质量过滤：愿意为工具付费的人，才有服务下级的意愿和能力。代理能力商品与级别服务商品的定位声明见十二章。

## 七、应用中心：流量的出口

### 7.1 定位与品类

应用中心把钱包的链上流量转化为第三方应用的分发与变现通道。它是**纯平台抽成，不参与团队归因、不进多级分账**。

品类分五块：官方精选（平台自有 IM 工具）、IM 社交、跨境电商、Web3 类（严格审核，跳系统浏览器或钱包 Tab）、我的（最近打开与上架申请入口）。

与交易的边界很清楚：交易卖的是**商品**（单次交易、官方上架、进多级分账）；应用中心分发的是**应用**（持续分发、合作方上架、平台单方抽成、周期结算）。

### 7.2 收益模式

四条变现通道：**分发抽成（用户经 Node 下载安装 App，T+7 结算）、推广位广告（合作方投放推广位或 Banner，T+30）、交易抽成（用户经 Node 进入 App 后完成交易，T+30）、生态联合**（HRCs 代币合作、跨生态空投，按协议）。具体费率按协议定稿。

上架流程是：提交申请 → 四道审核（资质、应用安全、内容合规、业务模式）→ 签协议定抽成 → 上架 → 持续监控与违规下架。

跨平台存在客观差异：iOS 只能跳转 App Store（欧盟 DMA 侧载除外），实际退化为**应用导航站**；Android 可直接分发 APK。两端 UI 一致，差异只在跳转逻辑。

### 7.3 行业监管与上架要求

这一节对合作方尤其重要，因为加密类应用现在最大的成本不是开发，而是上架。

**关键结论**：Google Play 已公开澄清「非托管钱包不在其加密政策适用范围内」。Node 是纯自管、不托管用户私钥的钱包，天然落在监管压力最小的一侧——这是我们相对托管型钱包最大的结构性优势。

| 平台 / 法规 | 关键要求 | 对 Node 的影响 |
|-|-|-|
| **Google Play**（2025-10 新政） | 加密交易所/钱包在 15+ 法域（美/英/欧/加/瑞/日/港/韩/以/南非/阿联酋等）须持牌；Google 后续澄清非托管钱包不在范围 | 自管定位免持牌，需保留「非托管」举证材料 |
| **Apple App Store 3.1.5** | 企业账号发布；交易所仅限已持牌地区；禁 DApp 浏览器、禁设备挖矿 | 产品已按此设计，不内嵌 DApp 浏览器、不做撮合 |
| **欧盟 MiCA + DORA** | CASP 须授权；托管服务另有清算义务；2025-01 起叠加 DORA 风险与事件报告义务 | 不托管不撮合即不落入 CASP，进入欧盟前需法律意见书 |
| **中国大陆安卓** | 涉加密应用不上架；常规上架需软著、ICP 备案、应用安全评估 | 采用自有渠道分发 |
| **其他监管中心** | 新加坡 MAS（数字支付代币牌照）、香港 SFC（第 1 类与第 7 类）、迪拜 VARA | 分区域合规运营 |

基于以上，Node 主动设了三条产品红线：**不托管用户私钥、不做加密货币撮合交易、不内嵌 DApp 浏览器**。这三条既是合规策略，也是产品边界——它们让 Node 可以在主流应用商店长期存续，而这是绝大多数加密项目做不到的。

### 7.4 给合作方的价值主张

相比传统应用市场，Node 应用中心的差异在于：流量是钱包原生用户，自带链上地址与资产；用户可以通过 DID 通行证一次签名登录，不必在每个应用重复注册；变现方式不止下载跳转，还包括推广位、交易抽成与生态联合；分发结算 T+7，快于行业惯例；合规责任上，合作方自带资质，Node 只做审核与分发，不替合作方背合规责任。

## 八、身份：信任的底座

### 8.1 福利特权

福利分三类：空投福利（定期向符合条件用户空投 USDRs、HRCs）、资产福利（体验商品、试用权益、限时卡券）、互动福利（签到、任务、活动奖励）。

所有福利领取都要过设备指纹校验。这是反女巫的统一闸门，也是为什么福利发得出去而不被脚本薅空。

### 8.2 安全保险库

保险库采用三级钥匙体系。**L1 设备指纹钥匙已上线：一台设备同一时刻只绑一个钱包，冷密钥由设备指纹派生，私钥永不上传。L2 生物特征钥匙（人脸等）用于高价值操作二次确认，L3 强生物特征钥匙**用于极高价值资产的托管级校验，两者均在规划中。

更重要的是，保险库不是一个孤立功能，而是四个模块的前置闸门：福利特权、团队、身份（短号绑定与 DID 激活）均要求设备指纹；**交易要求设备指纹并且必须已绑定团队**；应用中心不强制（部分权益领取除外）。

保险库还有一组规划中但尚无详细设计的延伸能力，值得单独提及，因为它指向 Node 的长期价值：

- **钥匙管理**：多钥匙分级授权、钥匙轮换与吊销
- **资产托管信托**：遗产继承、大额托管、条件释放
- **保险库服务**：资产保险、紧急冻结、异常找回
- **联合签名**：多设备多签确认高价值操作

这些能力现在看是安全功能，但往后走，钥匙管理与资产托管信托是可以独立收费的服务层——这是钱包从工具走向金融基础设施的路径。

### 8.3 数字身份通行证

当前已上线的是被动授权模式：第三方 App 拉起 Node 授权面板 → 用户选择签名主体（Web3 地址或 Web2 本地凭证）→ 输入 6 位本地 PIN → 本地私钥签名（私钥不出设备）→ 返回签名凭证完成登录。

演进方向是打通应用身份节点：IM 应用可用 Node 地址登录并在应用内直接调起转账；DApp 可通过 Node 连接钱包而无需自建钱包体系；Web2 应用可通过 DID 实现无密码登录；最终一个 Node 身份通行多个应用，权益与信用可携带。

需要说清的边界是：首期只做被动授权，**不主动打通第三方身份节点**。主动打通属演进目标，不构成上线承诺。

### 8.4 身份模块的战略含义

福利特权让用户留下来；保险库让平台敢发资产、敢做高价值交易；DID 通行证让 Node 从一个 App 变成别人依赖的基础设施。简单说：**钱包 / 团队 / 交易 / 应用中心决定 Node 能赚多少钱，身份模块决定 Node 能值多少钱。**

## 九、商业模式

### 9.1 收入结构

| 收入线 | 计费方式 | 结算 |
|-|-|-|
| 官方商品池交易 | 商品毛利（级差返利属分销成本） | 成交即结算 |
| 靓号发行 | 5 位基价 1000 USDT 等值，每多一位 ×0.9，号型 ×3 至 ×50 | 成交即结算 |
| 二级市场手续费 | 拍卖 2.5%；一口价 0%（引流）；租赁与赠送按协议定稿 | 成交即结算 |
| 应用中心 · 分发抽成 | 按协议定稿 | T+7 |
| 应用中心 · 推广位 | 按协议定稿 | T+30 |
| 应用中心 · 交易抽成 | 按协议定稿 | T+30 |
| 生态联合 | HRCs 合作、跨生态空投，按协议 | 按协议 |

口径说明：级差返利与多级佣金是**分销成本**，不是平台净收入。一口价 0% 手续费是刻意的引流设计——先把流动性做起来，手续费在拍卖和租赁上收。

### 9.2 三个飞轮

**交易飞轮**：用户购买 → 上线获得返佣 → 返佣复投购买。

**关系飞轮**：绑定关系 → 发展下级 → 积分累积升级 → 更高返佣比例 → 更强发展动力。

**资产飞轮**：购买资产 → 持有 → 进入二级市场流转 → 稀缺资产增值 → 吸引更多人进入一级市场。

三个飞轮相互咬合，但都以真实商品成交为源头，而不是以代币价格为源头。这是 Node 与多数 Web3 项目在商业模型上的根本差异。
