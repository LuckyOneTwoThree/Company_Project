# Node 合约测试用例框架

> **产出日期**：2026-07-31
> **覆盖范围**：v1.0 版本基线已上线合约（ReferralRegistry / GoodsMarket / AgentReward / AgentLevel / AgentPoints / RewardClaim / FixedPriceMarket / AuctionHouse / GiftChannel / ISkuRegistry / TradeLedger）
> **依据**：《Node产品手册 v2.0》附录 D · 能力成熟度声明、《功能定版清单-2026-07-31》、各合约源码

## 一、合约耦合矩阵（测试覆盖骨架）

8 条核心耦合链路，按风险分级：

| # | 耦合链路 | 涉及合约 | 风险等级 |
|---|---|---|---|
| L1 | **购买→返利链** | GoodsMarket.buy → AgentReward.onPurchase → ReferralRegistry.referrerOf → AgentLevel.rebateBps/compression → RewardClaim.addReward + AgentPoints.mint + AgentLevel.recordPoints | 🔴 最高 |
| L2 | **退货→撤返利链** | GoodsMarket.returnRequest → RewardClaim.returnReward（前置）→ GoodsMarket.approveReturn → AgentReward.revokeOrder → RewardClaim.revokeReward | 🔴 最高（P0/P1 漏洞所在） |
| L3 | **关系绑定链** | ReferralRegistry.bind/bindWithSig → DeviceRegistry.isBoundAddress + 防环 + set-once | 🔴 高 |
| L4 | **迁移治理链** | proposeMigration → approveMigration×2 + 时间锁 → executeMigration + supersededBy + resolve() 重定向 | 🟠 高（**本版未上线，见第八节**） |
| L5 | **流转跨渠道锁链** | FixedPriceMarket/AuctionHouse/GiftChannel.listSku → ISkuRegistry.lockSku → 跨渠道互斥 → channelTransfer + unlockSku | 🟠 高 |
| L6 | **升级审核链** | AgentLevel.requestUpgrade（快照 metric）→ miner approveUpgrade(enforceThreshold) | 🟡 中 |
| L7 | **团队积分累加链** | GoodsMarket.buy(feedTeamPoints) → AgentLevel.recordPoints → 沿 E 链 teamDepth 层累加 | 🟡 中 |
| L8 | **购买即绑定链** | GoodsMarket.buy → ReferralRegistry.bindOnPurchase（已绑定则静默跳过） | 🟠 高 |

## 二、L1 · 购买→返利链测试用例（最高优先级）

### 2.1 正向分账

| 用例 ID | 场景 | 预期 |
|---|---|---|
| L1-01 | 3 层上线全部合格（rank≥1），compression 开 | 每层按 `rebateBps[该层rank][layer]` 分润，3 个 RewardClaim 各加额度 |
| L1-02 | basis=0（原价）vs basis=1（成交价） | base 取值正确（gross vs net），返利金额随之变化 |
| L1-03 | 阶梯折扣触发（≥10 件 70%） | net 正确计算，返利按 net（当 basis=1）或 gross（当 basis=0） |
| L1-04 | 多币支付（USDRs/RC/HRCs） | `claimFor[payToken]` 路由到对应单币 RewardClaim，币种不串 |

### 2.2 compression 动态压缩（核心边界）

| 用例 ID | 场景 | 预期 |
|---|---|---|
| L1-05 | L1 上线 rank=0，compression 开 | 跳过 L1，名额上卷给 L2（L2 按 layer=1 拿返利） |
| L1-06 | L1+L2 均 rank=0，compression 开 | 两层都跳过，L3 按 layer=1 拿返利 |
| L1-07 | compression 关，L1 rank=0 | 该层作废（浪费名额），L2 仍按 layer=2 拿返利 |
| L1-08 | 全链 rank=0，compression 开 | 走 maxCompressionSkips=20 后停止，totalPaid=0 |
| L1-09 | 链深度 < layers（只有 2 层上线） | filled=2 后 cur=address(0) 退出，不报错 |

### 2.3 安全护栏

| 用例 ID | 场景 | 预期 |
|---|---|---|
| L1-10 | 返利金额 < minRebate（去尘） | 该层跳过不发 |
| L1-11 | 返利 > maxRebatePerLayer | 封顶为 maxRebatePerLayer |
| L1-12 | 整单 totalPaid > maxTotalPerOrder | **revert**（链上保护） |
| L1-13 | 防自推（cur == buyer） | 跳过该层不发 |
| L1-14 | 同一 refId 二次调用 onPurchase | **revert "AR: order used"**（幂等） |
| L1-15 | 非授权调用 onPurchase | **revert "AR: not rewarder"** |
| L1-16 | claimFor[payToken] 未配置 | **revert "AR: no claim for token"** |

### 2.4 钩子失败容忍（GoodsMarket try/catch）

| 用例 ID | 场景 | 预期 |
|---|---|---|
| L1-17 | AgentReward.onPurchase revert | 主交易**不回滚**，发码成功，emit `RebateHookFailed` |
| L1-18 | AgentPoints.mint revert | 主交易**不回滚**，发码成功（积分静默失败） |
| L1-19 | AgentLevel.recordPoints revert | 主交易**不回滚**（团队积分静默失败） |
| L1-20 | **未做双向授权**（AgentReward.setRewarder 未授权 GoodsMarket） | 钩子静默失败，购买成功但无返利（**配置陷阱，需告警**） |

## 三、L2 · 退货→撤返利链测试用例（P0/P1 漏洞重点）

### 3.1 正常退货流程

| 用例 ID | 场景 | 预期 |
|---|---|---|
| L2-01 | 退货前未领取返利 | approveReturn → revokeOrder 逐层 revokeReward 成功，code 状态 3，退款到买家 |
| L2-02 | 退货前上线已领取返利，买家先 returnReward | approveReturn 成功，已退回的额度在 RewardClaim 释放 |
| L2-03 | 部分层已领、部分未领 | revokeOrder 对未领层 revoke，已领层由 returnReward 处理（自动跳过） |

### 3.2 P0/P1 已知漏洞回归（必须覆盖）

| 用例 ID | 场景 | 预期（当前行为）| 风险 |
|---|---|---|---|
| L2-04 | **P0：直写奖励 rewards[] 退货无法自动撤销** | approveReturn 不撤销 rewards[] 写入的 RewardClaim 额度，买家可领了直写奖励再退货 | 🔴 需矿工后台兜底 |
| L2-05 | **P1：approveReturn 不校验奖励退回状态** | miner 可在未 returnReward 的情况下 approveReturn，已领返利不回收 | 🔴 需矿工流程约束 |
| L2-06 | 验证矿工后台硬性流程兜底：先 returnReward 再 approveReturn | 流程正确时无资金损失 | 验证兜底有效性 |

### 3.3 退货边界

| 用例 ID | 场景 | 预期 |
|---|---|---|
| L2-07 | 退货后 code 状态变 3，再次退货同一码 | **revert "GM: bad order"**（o.returned=true） |
| L2-08 | 非买家发起 returnRequest | **revert "GM: not buyer"** |
| L2-09 | 退货已转卖的码（codeOwner != buyer） | **revert "GM: bad code"** |
| L2-10 | 关系不解除验证 | 退货后 `referrerOf[buyer]` 不变（铁律） |

## 四、L3 · 关系绑定链测试用例

### 4.1 set-once 铁律

| 用例 ID | 场景 | 预期 |
|---|---|---|
| L3-01 | 已绑定用户再次 bind | **revert AlreadyBound** |
| L3-02 | bindOrphan 后 claimOrphan 改上级 | referrerOf 变更为 newReferrer，inPendingPool=false |
| L3-03 | claimOrphan 后再次 claimOrphan | **revert NotPending** |
| L3-04 | 退货后 referrerOf 不变 | 铁律验证（关系永久） |

### 4.2 防环与防自推

| 用例 ID | 场景 | 预期 |
|---|---|---|
| L3-05 | A→B→C，C 尝试 bind A | **revert CycleDetected** |
| L3-06 | 自己 bind 自己 | **revert SelfRef** |
| L3-07 | 绑定未注册的 referrer | **revert RefNotRegistered** |
| L3-08 | 128 层深度防环检测 | 超过 128 层链路时停止遍历，不 revert（边界） |

### 4.3 设备指纹耦合

| 用例 ID | 场景 | 预期 |
|---|---|---|
| L3-09 | DeviceRegistry 未绑定地址调 bind | **revert DeviceNotBound** |
| L3-10 | DeviceRegistry 为 address(0) | 跳过设备校验（兼容部署） |

### 4.4 EIP-712 签名绑定

| 用例 ID | 场景 | 预期 |
|---|---|---|
| L3-11 | bindWithSig 签名正确 | 验签通过，绑定成功 |
| L3-12 | bindWithSig 签名错误 | **revert BadSig** |
| L3-13 | bindWithSig 超时 | **revert Expired** |
| L3-14 | bindWithSig 跨链重放（chainId 不同） | DOMAIN_SEPARATOR 不同，验签失败 |
| L3-15 | 非 miner 提交 bindWithSig | **revert NotMiner** |

## 五、L4 · 迁移治理链测试用例

> ⚠️ **本版未上线**：关系转移 / 地址迁移 / 治理迁移能力 v1.0 未上线。以下用例为迁移能力上线后的回归储备，**本版不纳入测试范围**，仅作设计验证与合约接口预留参考。

| 用例 ID | 场景 | 预期 |
|---|---|---|
| L4-01 | 2 miner approve + 时间锁到期 executeMigration | 新地址继承上级/层级/短号，旧地址 supersededBy 重定向 |
| L4-02 | 仅 1 miner approve 就 executeMigration | **revert MigNotReady**（需 2/2） |
| L4-03 | 时间锁未到期 executeMigration | **revert MigNotReady** |
| L4-04 | 迁移后旧地址下线 resolve() 自动跟随 | `referrerOf[下线]` 仍指向旧地址，但 resolve() 返回新地址 |
| L4-05 | 迁移后旧地址 codeOf=0，新地址继承短号 | addrOfCode[c] = 新地址 |
| L4-06 | 迁移到已绑定地址 | **revert AlreadyBound** |
| L4-07 | 8 层嵌套 resolve 重定向上限 | 第 8 层后停止，返回当前（边界） |
| L4-08 | 重复 proposeMigration 同一 (from,to) | **revert MigExists** |

## 六、L5 · 流转市场跨渠道锁测试用例

## 九、跨合约组合边界场景（最容易出 bug）

> ⚠️ X-01~X-05 涉及迁移能力，**本版未上线，不纳入测试**，仅作迁移上线后的组合回归储备。本版重点测试 X-06~X-08。

| 用例 ID | 场景 | 预期 |
|---|---|---|
| X-01 | 迁移中的地址（已 proposeMigration 未 execute）发生购买 | referrerOf 仍指向旧地址，返利正常发到旧地址（resolve 未生效前）**【迁移未上线】** |
| X-02 | 迁移 execute 后，旧订单的 revokeOrder | orderRefIds 仍有效，revokeReward 正常 **【迁移未上线】** |
| X-03 | 上线迁移后，下线购买触发返利 | resolve() 跟随，返利发到新地址 **【迁移未上线】** |
| X-04 | compression + 迁移组合：上线已迁移，compression 跳过 | resolve 后取新地址 levelOf，按新地址 rank 判断 **【迁移未上线】** |
| X-05 | 短号挂单（lockSku）期间，原 owner 迁移地址 | skuOwner 仍是旧地址，新地址无法操作该挂单 **【迁移未上线】** |
| X-06 | 退货退款金额 > 合约余额 | **revert "GM: refund fail"**（需 miner 确认合约余额充足） |
| X-07 | 多 miner 配置（3 个 miner），2 个被移除剩 1 个 | removeMiner 拒绝移除最后一个 |
| X-08 | paused 状态下用户写操作全部 revert，miner 写操作仍可用 | 验证 whenNotPaused / onlyMiner 边界 |

## 十、测试策略

### 10.1 测试分层

| 层级 | 工具 | 覆盖范围 |
|---|---|---|
| **单元测试** | Foundry forge | 单合约函数级（权限校验、状态机、view） |
| **集成测试** | Foundry forge | 跨合约耦合链路（L1-L8 全部） |
| **模糊测试** | Foundry fuzz | compression 上卷步数、返利金额计算、防环检测 |
| **不变式测试** | Foundry invariant | set-once 不可改、总返利 ≤ maxTotalPerOrder、code 状态机单向 |

### 10.2 优先级

- **P0 必跑**：L1（购买返利）、L2（退货撤返利，含 P0/P1 漏洞回归）、L3（set-once 铁律）
- **P1 重要**：L5（跨渠道锁）、L8（购买即绑定）、X（组合边界）
- **P2 常规**：L4（迁移治理）、L6（升级）、L7（团队积分）

### 10.3 重点不变式（invariant testing）

```
1. set-once：bound[user] 一旦 true 永远 true（迁移除外，但迁移后旧地址 bound=false）
2. code 状态单向：0→1→2→3，不可逆（无 reset 方法）
3. 总返利 ≤ maxTotalPerOrder（当 maxTotalPerOrder > 0）
4. SKU 同一时刻只被一个渠道锁定
5. referrerOf 无环（_noCycle 保证）
6. 等级 ≤ MAX_LEVEL=10
7. rebateBps ≤ 10000
```
