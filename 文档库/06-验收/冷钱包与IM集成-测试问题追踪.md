## 一、P1 - 主要问题（3 项，需尽快修复）

### 1.1 冷钱包 - swap

**CW-S02 确认兑换按钮状态卡住 [P1]**

- **模块**：冷钱包 - swap
- **现象**：输入数量点击"确认兑换"后，输入密码并点击"确认"对话，按钮有时会卡住，显示灰色的"确认兑换"，过一会才变为"兑换中"。重启 App 后的首次兑换尤为常见。
- **排查方向**：
  - 检查密码确认弹窗关闭与主流程按钮状态切换之间的时序，确认是否存在主线程阻塞或状态更新延迟
  - 排查首次兑换时的初始化耗时（如合约实例化、gas 预估缓存预热、网络请求）是否阻塞了按钮态切换
  - 确认按钮置灰逻辑是否误用了"loading"占位，导致 UI 先卡在灰色态再异步切到"兑换中"
- **期望**：点击"确认"后立即将按钮状态切换为"兑换中"（loading 态），不出现长时间灰色"确认兑换"卡住的情况；首次兑换与后续兑换表现一致。

### 1.2 IM - Node 登录集成

**IM-N01 IM 调起 Node 登录时账号列表缺失 [P1]**

- **模块**：IM - Node 登录集成
- **现象**：在未打开 Node App 的情况下，IM 调起 Node 进行登录时，只进入到了"服务页面"，没有展示账号列表，用户无法选择账号完成登录。
- **排查方向**：
  - 检查 IM 调起 Node 的 deeplink / scheme 参数，确认是否携带了"登录场景"标识，Node 是否据此进入登录流程而非默认服务页
  - 排查 Node App 冷启动场景下的账号列表加载逻辑：是否在未完全初始化时提前跳转到了默认页
  - 确认 Node 在被外部调起时的路由优先级：登录场景应优先展示账号选择，而非服务首页
- **期望**：无论 Node App 是否已打开，IM 调起 Node 登录时都应进入账号列表页供用户选择账号完成登录。

**IM-N02 Node 登录验证弹窗未关闭导致 IM 账号切换失败 [P1]**

- **模块**：IM - Node 登录集成
- **现象**：IM 通过 Node 登录后，Node 侧的登录验证弹窗未自动关闭。当前若用户返回并切换用户重新验证登录，IM 那边实际并未完成账号切换，仍停留在原来的账号。
- **排查方向**：
  - 确认登录验证完成的回调时机：是否在 Node 弹窗关闭前就将结果回传 IM，导致状态不同步
  - 排查 Node 弹窗生命周期与登录态提交的先后顺序：应在登录态确认写入后再关闭弹窗，或关闭与回传作为原子操作
  - 检查切换用户场景下的旧登录态清理逻辑：新验证流程发起前是否未清理上一次未完成的会话
- **期望**：IM 通过 Node 完成登录验证后，Node 的登录验证弹窗自动关闭；切换用户重新登录时，IM 侧账号能正确切换为新账号，不残留旧账号会话。

## 二、P2 - 次要问题（3 项，迭代优化）

### 2.1 冷钱包 - 水龙头

**CW-F01 水龙头未绑定设备指纹时强制跳转引导页 [P2]**

- **模块**：冷钱包 - 水龙头（faucets）
- **现象**：在未于保险库添加设备指纹的情况下进入水龙头页面，会直接跳转至引导页面。逻辑判断本身正确，但强制跳转导致用户连续返回时卡在引导页无法退出。
- **排查方向**：
  - 将"自动跳转引导页"改为"在页面内展示引导卡片 + 手动点击前往设置"
  - 保留进入水龙头页的入口可见性，引导用户主动操作，不破坏返回栈
- **期望**：未绑定设备指纹时进入水龙头页面，不自动跳转，而是在页内提示并提供"前往设置"按钮，由用户手动点击进入；返回操作能正常退出水龙头页面。

### 2.2 冷钱包 - swap

**CW-S01 滑点容忍度与 gas 费用展示时机 [P2]**

- **模块**：冷钱包 - swap
- **现象**：当前在未输入兑换数量时，下方就已展示滑点容忍度及相关详情；预估 gas 费用的展示方式也不够紧凑。
- **排查方向**：
  - 调整滑点容忍度及相关详情的展示条件：仅在用户输入兑换数量后才展示
  - 预估 gas 费用改为"点击详情 → 下拉展开"的折叠展示形式，完整 gas 费用明细放在下拉内容中，默认收起
- **期望**：输入前不展示滑点容忍度与相关详情；输入后才展示。预估 gas 费用默认收起，点击"详情"下拉展开完整费用明细。

### 2.3 IM - 钱包切换

**IM-W01 钱包功能迁移提示展示时机 [P2]**

- **模块**：IM - 钱包切换
- **现象**：IM 切换到钱包时提示"钱包功能迁移"，当前流程是"先展示提示 → 用户确认 → 再切换到钱包页面"，提示先于页面切换出现。
- **排查方向**：
  - 调整交互顺序：先切换到钱包页面，再在钱包页面内展示"钱包功能迁移"提示
  - 确认提示的展示形式（弹窗 / Toast / 页内横幅）与确认逻辑是否需要保留
- **期望**：切换到钱包页面后再展示"钱包功能迁移"提示，不要先展示提示再确认再切换。
