# 特权福利服务 产品逻辑设计

> 本文档描述福利特权中心的完整产品逻辑，包含空投、持仓返利、生态激励、会员权益、分销推广等所有子场景。
> 版本：v2.0
> 日期：2026-06-04

---

## 一、服务定位

福利特权中心是 IM 开放服务中的核心服务之一，**包含激励空投服务**，并在此基础上扩展了更丰富的福利场景。服务本质是统一的 **"核验条件 + 触发分发"** 模式——无论推出什么新活动，后端逻辑一致，运营在后台配置规则即可上线，无需重新开发。

### 1.1 代币命名约定

| 代币 | 说明 | 场景 |
|------|------|------|
| **USDR** | 平台主要代币 | 空投、返利、签到等主要奖励币种 |
| **RC** | 自主链 Gas 原生代币 | Gas 补贴、链上交互手续费 |
| **HRC** | 生态联合 Token | 跨项目联合激励、合作方空投 |

### 1.2 钱包体系

| 类型 | 用户端展示名 | 说明 |
|------|------------|------|
| 平台托管钱包 | 平台托管钱包 | 默认高频交互地址，平台代管用户资产 |
| IM 本地钱包 | **自管钱包** | 本地多链多账户钱包，用户自主控制私钥 |
| 外部绑定钱包 | 外部钱包 | MetaMask / WalletConnect 等第三方钱包 |

> **注意**：技术层面的标识（cold / platform / external）保持不变，仅用户端展示名称统一为"自管钱包"。

## 二、领取条件（触发器体系）

为了实现后端的模块化，将所有触发奖励的条件抽象为三大类"触发器"（可按服务逻辑增加）：

### 2.1 行为触发类

| 触发器 | 说明 | 典型场景 |
|--------|------|---------|
| 账户动作 | 首次开通平台托管钱包（校验历史是否生成过地址） | 迎新 Gas 补贴 |
| 活跃动作 | 每日登录、进入中心点击"领取"等用户操作 | 每日奖励空投 |

### 2.2 资产快照类

| 触发器 | 说明 | 典型场景 |
|--------|------|---------|
| 门槛持仓 | 校验绑定地址的特定资产余额（如 USDR 余额 ≥ 500） | 持仓返利 |
| 特定资产 | 校验绑定地址是否持有指定的 Token 代币 | 生态联合空投 |
| 特定名单 | 校验绑定地址是否属于平台预配置的白名单 | 种子用户空投、VIP 专属 |

> **白名单核验逻辑**：白名单由运营方在后台预先配置，服务端请求并核验用户是否在名单中。用户端点击"核验白名单资格"，服务端比对后返回结果，**非用户端碰撞验证**。

### 2.3 业务订单类

| 触发器 | 说明 | 典型场景 |
|--------|------|---------|
| 消费核验 | 业务中台抛出的"已支付成功"订单事件 | 购买高级会员、硬件商城下单 |
| 关系链核验 | 社交裂变判定的有效邀请关系及下级有效流水 | 分销返佣 |
| 其他 | 后续通过新业务判断 | - |

## 三、下发方式

### 3.1 三种标准化路径

| 下发方式 | 逻辑 | 适用场景 | 用户端展示 |
|---------|------|---------|-----------|
| **自动下发** | 满足条件后，后端脚本自动将奖励打入用户地址 | 开通钱包送微量 RC、消费返利即时到账 | ⚡标签 + "自动下发"提示卡片 |
| **手动领取** | 满足条件后，用户必须主动点击"领取"，资产才会入账 | 专项空投、每日奖励 | 🎁图标 + "领取"按钮 |
| **周期性下发** | 达到门槛或固定周期（如每周一）统一下发 | 持仓返利每周自动下发 | ⚡标签 + "自动下发"提示卡片 |

### 3.2 多奖励项独立领取

一个方案可能包含**多条奖励项**，每条奖励可独立领取，非一次性全部领取。

**示例**：分销推广特权方案

| 奖励项 | 金额 | 下发方式 |
|--------|------|---------|
| 一级分销返利 | 8.5 USDR | 手动领取 |
| 二级分销返利 | 3.2 USDR | 手动领取 |
| 分销达标奖励 | 200 HRC | 手动领取 |

**数据结构**：

```json
{
  "rewards": [
    { "id": "r1", "title": "一级分销返利", "amount": "8.5 USDR", "auto": false },
    { "id": "r2", "title": "二级分销返利", "amount": "3.2 USDR", "auto": false },
    { "id": "r3", "title": "分销达标奖励", "amount": "200 HRC", "auto": false }
  ]
}
```

> 每条奖励领取后独立标记为已领取，互不影响。自动下发的奖励项不显示领取按钮，显示"⚡自动"标签。

### 3.3 历史累计奖励补领机制
在特定周期性考核方案（例如“USDR持仓返利”等按日/周快照返利的方案）中，允许用户补领历史已产生但未领取的返利奖励，从而提升用户体验与活跃留存。

#### 3.3.1 时限与生命周期管理
*   **可补领时限（配置参数）**：补领时限由后端规则参数 `reclaimLimitDays` 统一配置（默认支持 7 天、30 天或 90 天配置）。
*   **状态转移状态机**：
    *   **快照时间 $\le$ 补领天数上限** 且 **未领取** $\rightarrow$ `未领/可补领` 状态。
    *   **快照已领取** $\rightarrow$ `已领` 状态（不可重复补领）。
    *   **快照时间 $>$ 补领天数上限** 且 **未领取** $\rightarrow$ `已过期/已失效` 状态，对应的补领入口将强制禁用，奖励资金拨回合约池。

#### 3.3.2 用户端展示要素规范与批量补领
为了简化账目对比并提升操作效率，补领列表进行精简与批量优化：
1.  **移动端卡片式流布局(Card List Items)**：摒弃传统的 Table 报表模式，改为高保真卡片流展示。每条记录作为独立小卡片呈现：左侧展示自研的**自定义圆形复选框 (Circular Checkbox)** 与活动礼包小图标（为了界面清爽与重点突出，圆形多选框只在“未领”卡片上浮现，已领/失效状态卡片仅展示礼包图标以对齐视觉线）；中间排列快照时刻与持仓余额；右侧大号粗体显示加号形式的返利数值（如 +35.2 💎）与状态/操作按钮。移除冗余的 `dayIndex` 字段。
2.  **币种无文本后缀与币种微型图标**：为了界面的紧凑性和美观度，数字后面不再拼接 "USDR" 等字符串单位，统一使用高质感的微型币种图标（如微型钻石 💎 徽章）以图形化展示。
3.  **多选与批量补领交互优化**：
    *   **圆形自定义复选框**：使用自定义圆形 UI 代替系统默认的方形复选框。未选中时展示浅灰色极细空心圆，选中时呈现靛蓝色实心圆并微缩放渐现白色勾号 `✓`。
    *   **整行卡片点击勾选 (Card-Level Clicking Toggle)**：在手机 C 端中，为了省去用户费劲去点 20px 小圆圈的局限，点击未领卡片的除“单笔补领按钮”外的任何主体区域，可直接切换该卡片的勾选选中态，实现极具解压感的大范围热区操作。
    *   **一键全选可补领**：顶部全选栏提供对应的圆形自定义全选复选框，可同步全选/取消全选所有可领状态的历史记录。
    *   **一键批量补领已选 (N)**：页面底部常驻悬浮渲染“一键补领已选奖励 (N)”动作条，联动已勾选项数实时启用或置灰。
4.  **状态与操作**：
    *   `未领` $\rightarrow$ 浮现圆形复选框，可多选，卡片内渲染“补领”按钮，点击触发单笔补领。
    *   `已领` $\rightarrow$ 无圆形多选框，卡片内渲染“已补领”文本徽章。
    *   `已过期` $\rightarrow$ 无圆形多选框，卡片内渲染“已失效”文本徽章。

## 四、场景清单

### 4.1 迎新特权（一次性下发）

| 活动 | 触发器 | 奖励 | 下发方式 |
|------|--------|------|---------|
| 开通平台钱包 Gas 补贴 | 账户动作（首次开通） | 0.05 RC | 手动领取 |
| 迎新专项空投 | 特定名单（种子白名单） | 50 USDR | 手动领取 |

> Gas 补贴技术方案：水龙头（批量分发合约）或签名代付分发。

### 4.2 每日活动（周期性下发）

| 活动 | 触发器 | 奖励 | 下发方式 |
|------|--------|------|---------|
| 每日奖励空投 | 活跃动作（每日领取） | 2 USDR | 手动领取 |

### 4.3 特权白名单核验

| 活动 | 触发器 | 奖励 | 下发方式 |
|------|--------|------|---------|
| USDR 持仓返利 | 门槛持仓（USDR ≥ 500） | 按持仓比例返利 USDR | 手动领取 |
| USDR 持仓返利（自动） | 门槛持仓（USDR ≥ 500） | 按持仓比例返利 USDR | 自动下发 |
| 生态 Token 联合空投 | 特定资产（持有合作方 Token） | 1,200 HRC + 50 USDR | 手动领取 |

> **持仓返利定义**：持有 USDR 等代币按持仓比例获得代币返利，返利发放的也是代币（如 USDR），**非 Gas 原生代币免除**。

### 4.4 生态回馈

| 活动 | 触发器 | 奖励 | 下发方式 |
|------|--------|------|---------|
| 付费权益返利 | 消费核验（购买/续费高级会员） | 12.5 USDR（自动）+ 100 HRC（手动） | 混合 |
| 分销推广特权 | 关系链核验（有效邀请+下级流水） | 一级返利 + 二级返利 + 达标奖励 | 手动领取 |
| 硬件商城购买返利 | 消费核验（成功下单购买设备） | 待定 | 待定 |

## 五、用户核心流程

### 5.1 主页：选定地址

- 主页顶部展示**当前绑定的服务地址**（不展示钱包余额）
- 提供【切换校验身份】按钮，可切换平台托管 / 自管钱包 / 外部钱包
- 选择自管钱包时，需进一步选择**账户 + 链**（Web3 多链多账户逻辑）

### 5.2 活动列表：分类浏览

- 所有活动以**统一流式方块卡片**展示，顶部分类 Tab 筛选
- 分类：全部 / 空投 / 持仓返利 / 生态激励 / 会员权益 / 分销推广
- 即时领取类活动：卡片内嵌领取按钮，点击直接领取
- 白名单核验类活动：点击卡片进入方案详情页

### 5.3 详情页：地址锁定 + 核验 + 领取

进入详情页后，**当前地址强锁定，中途不允许更换**。流程如下：

**第一步：余额自检（可选）**
- 详情页提供【当前地址资产速查】功能（Oracle Snapshot）
- 用户可在核验前，通过 RPC 节点实时扫描该地址的代币余额
- 部分方案（如会员权益、分销推广）不需要余额查询，自动隐藏

**第二步：白名单资格核验**
- 详情页写明【奖励发放逻辑说明】（如：每周一自动下发）
- 用户点击【核验白名单资格】，服务端请求预配置白名单并核验
- 核验通过后：
  - 手动领取类：展示奖励列表，每条奖励有独立"领取"按钮
  - 自动下发类：展示"⚡自动下发模式"提示卡片，说明返利将自动发放
- 核验通过后，余额查询和核验卡片**默认收起**，用户可通过顶部按钮展开

**第三步：领取奖励**
- 每条奖励独立领取，领取后直接发放到绑定钱包
- 无需选择钱包/账户/链（已在入口处绑定）
- 领取成功后奖励卡片标记为已领取

### 5.4 方案内下发历史

- 每个方案详情页**右上角**有历史入口（📋按钮）
- 点击后滑入独立的下发历史页面，展示该方案所有下发记录
- 包含：奖励标题、金额、时间、链、交易哈希（支持一键复制）

### 5.5 全局领取记录

- 首页右上角记录入口
- 按**大模块 Tab 分类**筛选：全部 / 空投 / 持仓返利 / 生态激励 / 会员权益 / 分销推广
- 每条记录包含：标题、金额、时间、链、交易哈希（支持一键复制）
- 自动下发的记录标注"⚡自动"标签

## 七、与后台的关联

### 7.1 配置驱动

所有活动行为由后台配置驱动，服务端只负责执行逻辑：

| 配置项 | 对应后台模块 | 说明 |
|--------|------------|------|
| 活动基础配置 | ProductServiceParam | 名称、类型、时间、分类 |
| 链与合约配置 | ProductChainConfig + ProductContractConfig | 代币合约、平台钱包 |
| 触发器配置 | ProductServiceParam | 资格判定模式及附加参数 |
| 奖励配置 | ProductServiceParam → rewards[] | 多奖励项数组 |
| 下发方式配置 | ProductServiceParam | 手动/自动/周期性 |
| 过期策略配置 | ProductServiceParam | DESTROY / AUTO_CLAIM / EXPIRE / ROLL_OVER |
| 定时任务配置 | ProductServiceJobConfig | 快照周期、计算时间 |

### 7.2 数据隔离

所有数据按产品隔离（`productId`），不同产品的活动、快照、领取记录完全独立。

## 八、总结

福利特权中心的核心设计原则：

1. **统一模式**：所有活动本质都是"核验条件 + 触发分发"，后续上线新活动不需要重新写代码
2. **配置驱动**：运营在后台勾选规则即可上线，扩展性强
3. **多奖励项**：一个方案可包含多条奖励，独立领取，互不影响
4. **白名单核验**：白名单由运营预配置，服务端请求并核验，非用户端碰撞
5. **直接领取**：领取时直接发放到绑定钱包，无需选择钱包/账户/链
6. **分类清晰**：活动分类体系贯穿首页筛选、记录筛选、后台统计
7. **下发可追溯**：方案内下发历史 + 全局领取记录，交易哈希支持一键复制取证
