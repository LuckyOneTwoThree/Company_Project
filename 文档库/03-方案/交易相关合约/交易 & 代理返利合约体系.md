### 一、子系统数据流（一次商品购买发生了什么）

用户 buyer 调 GoodsMarket.buy(productId, qty, payToken) ── 同一笔交易内 ── 1) 校验 MOQ/黑白名单/上下架 → 按折扣阶梯算价 → transferFrom 收款 → treasury 2) 从唯一识别码台账分配 qty 个码给 buyer，记账（谁买了哪些码） 3) 若商品配了购买奖励 rewards[] → 逐条 RewardClaim.addReward(buyer, amount, refId) // 买家自身奖励 4) 若是「级别服务商品」 → AgentPoints.mint(buyer, points, refId) // 给买家加升级燃料 5) 调 AgentReward.onPurchase(buyer, productId, grossPrice, netPrice, payToken, refId) └─ 沿 ReferralRegistry(E) 上线链取 N 层
 └─ 每层按「该层上线自身等级」查 AgentLevel.rebateBps[rank][layer]（级差制）
 └─ compression 开：跳过未达标/未激活上线，名额上卷给上面下一个合格上线
 └─ 每层 RewardClaim.addReward(agent, rebate, refId') // 上线返利 各奖励接收人自付 gas 调 RewardClaim.claim() 领取（无中继、无 miner 手动）
退货：GoodsMarket 审核；前置硬条件＝先 returnReward 把奖励退回原 RewardClaim；逐层 revoke/return

### 三、返利模型定案（2026-07-20）

![🧭 标注图标](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==)

等级 vs 层级 是两个维度，别混：

等级 rank = 横向：以自己为起点的「团队级别」L1..10，L1 起始、逐级叠加权益。每个代理靠自身达标独立升级——A 是 L10 不会抬高其上线 +1/+2/+3 的等级（普众公平）。

层级 layer/depth = 纵向：单个订单里沿上线链的深度位（+1/+2/+3…）。

派发 = 级差制：每层返利按该层上线「自己的等级」取

rebateBps[rank][layer]

，不受下游等级影响。

动态压缩（烧伤）

compression

（默认开、可关）：某层上线若未达门槛/未激活，则跳过、名额上卷给上面下一个合格上线，避免名额浪费、强化升级动力。
