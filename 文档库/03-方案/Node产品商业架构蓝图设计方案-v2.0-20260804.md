## 一、设计原则(v2.0 调整说明)

### 1.1 v1.0 的问题

v1.0 共 15 章,存在三个问题:
1. **大而全**:护城河、竞品对比、B 端运营、网络效应等已定内容重复占用篇幅
2. **参与者缺失**:只讲"模块怎么连",没讲"谁触发、谁受益、谁审核"
3. **演进过细**:v2.0 远期细节(租赁/荷兰拍/集邮挖矿)占位过多,挤占当下焦点

### 1.2 v2.0 原则

| 原则 | 说明 |
|---|---|
| 聚焦耦合 | 只画模块间"谁调谁、谁依赖谁",商业逻辑只在耦合处一句话点出 |
| 参与者显性化 | 每个模块标注触发方 / 受益方 / 审核方 |
| 多留白 | 已定内容不重述(引用 v1.0 即可),演进只列预留点位置 |
| 图重于文 | 核心用 Mermaid 思维导图与流程图,文字只做注解 |
| 不重复 | 同一信息只在一处维护,其他引用编号 |

## 二、参与者地图(新增核心维度)

> 蓝图不仅要讲"模块怎么连",更要讲"谁在用"。同一模块对不同参与者意义不同,需显式标注。

### 2.1 参与者全景思维导图

```mermaid
mindmap
  root((Node 参与者))
    C 端用户
      普通用户(买家)
        触发购买
        获得资产
        产生返利给上线
      代理(卖家)
        代销或囤货
        赚取差价
        有上级有下级
      团长(高 rank)
        团队积分累加
        团队返利
        可兼任矿工
      矿工(miner)
        审核升级
        审核奖励
    B 端运营
      运营
        配置服务参数
        不能新增字段
      财务
        对齐 8 项财务参数
      开发
        定义能力边界
        声明参数 Schema
    系统层
      官方平台
        统一商品池发行
        treasury 收款
      合约层
        自动执行
        不可篡改
      应用第三方
        独立利润中心
        不参与团队归因
```

### 2.2 参与者能力边界

| 参与者 | 能做 | 不能做 | 利益来源 |
|---|---|---|---|
| **普通用户** | 购买商品、绑定上级、持有资产、流转处置 | 上架商品、领取团队返利 | 自身购买奖励、资产增值 |
| **代理** | 上述全部 + 代销/囤货、改价、补货、下架 | 越级看商品池(严格层级) | 代销差价 + 下级购买返利 |
| **团长** | 上述全部 + 团队积分累加、3 层团队返利 | 跳过等级 compression | 团队返利(沿 E 链 3 层) |
| **矿工** | 审核升级申请、获得审核奖励 | 自审自己 | 审核奖励 |
| **运营** | 配置产品参数、管理商品上架、查看数据 | 新增字段、改合约逻辑 | 平台薪资 |
| **财务** | 对齐 8 项参数、校准金额 | 改业务逻辑 | 平台薪资 |
| **开发** | 定义服务能力、声明 Schema、部署合约 | 改线上参数、改业务规则 | 平台薪资 |
| **官方平台** | 统一发行商品、treasury 收款、空投 | 托管私钥、改链上关系 | 货款 + 手续费 |
| **应用第三方** | 上架应用、获得 CPS 抽成 | 参与团队归因、触达关系层 | CPS 抽成 + 上架费 |

### 2.3 身份叠加规则(同一地址可兼任)

| 兼任组合 | 触发条件 | 利益叠加 |
|---|---|---|
| 普通用户 + 代理 | 有上级且自身有下级 | 买时代理赚差价,卖时赚团队返利 |
| 团长 + 矿工 | rank ≥ 阈值(待定) | 团队返利 + 审核奖励 |
| 官方 + 商家 | 平台自营商品 | treasury 收款 + 商品利润 |
| 代理 + 矿工 | 代理 rank 达标 | 代销差价 + 审核奖励 |

> **关键**:身份不是注册出来的,是链上状态自动判定的。地址的 rank、上下级关系、持仓决定了它当下是哪个身份,合约层无歧义。

## 三、功能模块全景(思维导图)

> 按**商业职能分层**(L1-L7),非按 Tab 分层。Tab 是用户视角,分层是架构视角。

```mermaid
mindmap
  root((Node 产品模块))
    L1 基础层
      自管钱包
      代币体系 RC USDRs HRCs RSTs
      Swap 兑换
    L2 关系层
      设备指纹 DeviceRegistry
      关系绑定 ReferralRegistry
    L3 资产层
      商品发行 GoodsMarket
      短号中心 ShortNumRegistry
      SKU 资产抽象 ISkuRegistry
      代销体系 v1.x 规划
    L4 返利层
      级差返利 AgentReward
      双积分 AgentPoints
      等级升级 AgentLevel
      奖励领取 RewardClaim
    L5 流转层
      一口价 FixedPriceMarket
      拍卖 AuctionHouse
      赠送 GiftChannel
      租赁 RentalChannel v1.x 规划
      台账 TradeLedger
    L6 身份层
      DID 通行证
      福利特权
      保险库 L1
    L7 应用层
      应用中心 独立
```

### 3.1 分层依赖铁律

- **上层依赖下层,下层不感知上层**(单向依赖)
- L2 关系层是分水岭:L1+L2 构成"信任基座",L3-L5 构成"商业引擎",L6-L7 构成"生态扩展"
- L7 应用中心**独立于 L2-L6**,不参与关系与分润(合规防火墙)

### 4.2 八条核心耦合链路(最易出问题)

> 每条链路标注:触发方 → 涉及模块 → 受益方,审核方单独标注

#### 链路 1:购买 → 返利(最高频)

```mermaid
sequenceDiagram
  autonumber
  participant 买家 as 买家(普通用户)
  participant GM as GoodsMarket(L3)
  participant RR as ReferralRegistry(L2)
  participant AR as AgentReward(L4)
  participant AL as AgentLevel(L4)
  participant RC as RewardClaim(L4)
  participant AP as AgentPoints(L4)
  participant 上线 as 上线(代理/团长)

  买家->>GM: buy()
  GM->>RR: referrerOf(买家)
  RR-->>GM: 返回 L1/L2/L3 上线
  GM->>AR: onPurchase()
  AR->>AL: levelOf(各上线 rank)
  AL-->>AR: rebateBps[rank][layer]
  AR->>RC: addReward(3 层额度,冻结)
  RC-->>上线: 7/14/30 天后可领
  AR->>AP: mint(买家个人积分)
  AR->>AL: recordPoints(沿 E 链团队积分)
```

- **触发方**:买家(普通用户)
- **受益方**:3 层上线(代理/团长)+ 买家自身
- **风险点**:返利计算错误、compression 失效

#### 链路 2:退货 → 撤返利(P0/P1 漏洞高发区)

```mermaid
sequenceDiagram
  autonumber
  participant 买家 as 买家
  participant GM as GoodsMarket(L3)
  participant AR as AgentReward(L4)
  participant RC as RewardClaim(L4)
  participant 上线 as 上线

  买家->>GM: returnRequest()
  GM->>买家: 硬条件:先 returnReward
  买家->>RC: returnReward(已领额度)
  GM->>AR: 沿链 revoke(未领额度)
  AR->>RC: 自动抵扣(已领从后续佣金扣)
  GM-->>买家: 退款(只退钱,不解除关系)
```

- **触发方**:买家
- **审核方**:合约自动(compression 链路)
- **受益方**:平台(避免双重支付)
- **关键铁律**:退货只退钱,**不解除关系**

#### 链路 3:关系绑定 → 设备指纹(全 App 闸门)

```mermaid
flowchart LR
  A[钱包地址] --> B{设备指纹绑定?}
  B -- 未绑定 --> C[DeviceRegistry.bind]
  C --> D[生成冷密钥]
  D --> E[绑定成功]
  B -- 已绑定 --> F[拒绝]
  E --> G[ReferralRegistry.bind 可执行]
  G --> H[5 渠道归因 set-once]
```

- **触发方**:新用户
- **审核方**:DeviceRegistry(物理层排他)
- **受益方**:上级(获得归因)
- **风险点**:绕过设备指纹直接绑定

#### 链路 4:购买即绑定(bindOnPurchase)

```mermaid
flowchart LR
  A[买家未绑定上级] --> B[购买商品]
  B --> C{seller 有上级?}
  C -- 有 --> D[bindOnPurchase 绑到 seller 上级]
  C -- 无 --> E[绑到 seller 自身]
  D --> F[归因链路建立]
  F --> G[后续购买触发返利]
```

- **触发方**:买家(隐式)
- **受益方**:seller 的上线
- **风险点**:bindOnPurchase 逻辑错误导致归因错位

#### 链路 5:升级 → 返利比例变化

```mermaid
sequenceDiagram

  participant 矿工 as 矿工
  participant AL as AgentLevel(L4)
  participant 财务 as 财务(参数对齐)

  代理->>AL: 积分达标,申请升级
  矿工->>AL: 审核通过
  AL->>AL: rank 提升(1-10)
  AL->>AL: 切换 rebateBps 矩阵

```

- **触发方**:代理(申请)
- **审核方**:矿工
- **受益方**:代理(返利比例提升)

## 六、核心商业闭环(精简,仅资金流)

> v1.0 有三大流(资金/价值/关系),v2.0 只保留技术最必需的资金流时序,价值流与关系流已隐含在第四章耦合链路中。

### 6.1 资金流时序(用户付款后资金去向)

```mermaid
flowchart TD
  A[用户付款 USDRs/RC/HRCs] --> B[货款]
  A --> C[级差返利]
  A --> D[买家自身奖励]
  A --> E[积分 mint]
  A --> F[手续费]

  B --> B1[treasury 平台/商家收入]
  C --> C1[L1 上线 RewardClaim 冻结 7 天]
  C --> C2[L2 上线 RewardClaim 冻结 14 天]
  C --> C3[L3 上线 RewardClaim 冻结 30 天]
  C -.compression 未达标跳过.-> C4[名额上卷]
  D --> D1[rewards 数组写入买家]
  E --> E1[AgentPoints.mint 个人积分 Soulbound]
  E --> E2[AgentLevel.recordPoints 团队积分沿 E 链]
  F --> F1[各渠道独立 一级商城在货款内 拍卖 2.5%]
```

### 6.2 退款回滚(三重防护)

1. **前置硬条件**:退货前必须先 `returnReward` 退回奖励
2. **逐层 revoke**:AgentReward 沿链撤销未领取奖励
3. **自动抵扣**:已领取的从后续未领取佣金自动抵扣

**关键铁律**:退货只退钱,**不解除关系**(保护归因链路可信度)。
