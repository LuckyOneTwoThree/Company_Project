## 0. 设计总览

### 0.1 一句话定位

**流转市场 = 用户名下所有 SKU 资产(短号 + 商品码)的二手处置中心**,卖家在此挂单出售/出租/拍卖自己持有的资产,买家在此浏览并成交;前端聚合所有渠道合约的挂单,订单台账统一记录到 `TradeLedger`。赠送(`GiftChannel`)不在此挂单,但订单中心可见其记录。

### 0.2 四大设计动作(v2.1 调整)

1. **统一入口**:新建独立「流转市场」入口(身份 Tab 下,与短号中心平级),聚合商品流转与短号流转,避免按资产类型分散入口
2. **多渠道并存(v2.1 调整)**:P1 同时支持一口价(channelId=2)、拍卖(channelId=3)、租赁(channelId=5)三种成交模式;P3 接入荷兰拍(channelId=4);赠送(channelId=1)不在流转市场挂单,保留在短号中心/商品详情页入口
3. **统一台账**:所有成交写入 `TradeLedger`,链下派生跨渠道订单中心,用户在一个页面看到自己所有渠道的挂单与历史(含赠送记录)
4. **★ 市场单视图(v2.1 调整)**:默认且唯一视图为「市场浏览」(买方视角),**无底部 Tab**;「我的」作为右上角入口(个人中心);市场首页提供「渠道分类快捷切换」(全部/一口价/拍卖/租赁),用户可快速切换不同成交模式的挂单;挂售作为次级入口,仅藏在「我的 → 资产详情」内;运营设置完全移出 C 端,下沉至 B 端管理后台

> **对齐主流市场心智**:OpenSea / Blur / Magic Eden 一致采用「市场浏览为主视图 + 个人中心右上角入口 + 挂售藏在资产详情内」模式。二级流转本质是交易模式,以「买」为主,「卖」作为明显但不喧宾夺主的次级入口

### 0.3 与既有模块的边界

| 维度 | 商城(Tab 4) | 短号中心(Tab 2) | 流转市场(本模块) |
|------|------|------|------|
| **资产生命周期阶段** | 一级发行 | 持有管理 | 二级处置 |
| **角色** | 官方/代理发行新商品 | 用户持有短号资产 | 用户处置既有资产 |
| **渠道** | PRIMARY(channelId=0) | 直转/赠送(channelId=1/直转) | 一口价/拍卖/租赁(channelId=2/3/5) |
| **是否触发归因** | 直购触发 `bindOnPurchase` | 不触发 | **不触发**(铁律) |
| **是否分润** | 触发 `AgentReward.onPurchase` | 不触发 | **不触发**(铁律) |

> 流转市场是"二级市场",铁律:**所有渠道流水不纳入代理奖励分润**,这与合约层 `FixedPriceMarket` / `AuctionHouse` 等渠道的"奖励铁律"完全对齐。

## 1. 方案概述

### 1.1 背景

Node 体系内已有两种链上 SKU 资产:
- **商品码**:由 `GoodsMarket` 发行,用户购买后获得唯一码(`codeId`),可消费或转赠
- **短号**:由 `ShortNumRegistry` 发行,用户购买/领取后绑定到地址,作为身份资产

两种资产在合约层已统一抽象为 `ISkuRegistry`(`skuOwner` / `skuActive` / `channelTransfer` / `lockSku` / `unlockSku`),且都接入了 `TradeLedger` 统一台账。合约基建已支持 7 个渠道(channelId=0~7)。

但产品层存在三处缺口:
1. **入口分散**:商品码流转入口在商城内嵌(对齐 `GoodsMarket.Listing`),短号流转入口在短号中心(独立接口 `IShortNumberAsset` 预留),两者未打通
2. **渠道不全**:商品码当前仅支持一口价(`GoodsMarket.listItem`),短号仅支持转移/赠送,拍卖/租赁/荷兰拍未接入前端
3. **订单割裂**:跨渠道挂单与历史订单无统一视图,用户难以管理自己分散在多个渠道合约的挂单

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| 统一入口 | 流转市场作为独立模块,聚合商品码 + 短号两类资产的处置 |
| 多渠道并存 | 一口价(P1)、拍卖(P2)、租赁(P3)、荷兰拍(P3)四种渠道并存,用户可选最契合资产的处置方式 |
| 跨渠道订单中心 | 用户视角下,挂单/历史/收益统一展示,无需关心资产在哪个合约上 |
| 资产可发现 | 浏览者可按资产类型、渠道、价格、网络等多维度筛选市场挂单 |
| 风控完备 | 跨网络限制、保密商品脱敏、退货后作废码过滤、miner 多签运营 |

### 1.3 范围与不包含

- **包含**:流转市场入口、资产挂单流程(一口价/拍卖/租赁)、市场浏览页、跨渠道订单中心、收益结算展示、风控边界、与既有模块的集成关系、P1/P2/P3 阶段化路径
- **不包含**:
  - 合约层重新设计(完全沿用已有渠道合约,见各 [渠道合约文档](../交易相关合约/))
  - 碎片化流转(channelId=7 Fractional,合规风险高,暂不启动)
  - 一级发行流程(在商城/短号中心)
  - 资产消费/履约流程(在持有人视图,非处置视角)

## 2. 核心架构决策

### 2.1 决策矩阵(15 项 · v2.0 新增 2 项)

#### 入口与聚合(3 项)

| # | 决策点 | 结论 | 理由 |
|---|--------|------|------|
| 1 | 流转市场入口位置 | **身份 Tab(Tab 2)下,与短号中心平级,作为独立卡片** | 流转市场跨资产类型,不应挂在商城内(误导为一级发行);身份 Tab 已是"我有什么"的资产聚合视图 |
| 2 | 资产视图聚合方式 | **A2 全资产聚合视图**:统一展示短号 + 商品码,按 SKU 类型分类筛选 | 合约层已是统一抽象(`ISkuRegistry` + `TradeLedger`),前端聚合成本低;用户心智是"我有什么可处置",而非"我在哪个合约挂单" |
| 3 | 是否新建独立 Tab | **否,挂在身份 Tab 下** | 流转市场是低频功能,不足以独立成 Tab;身份 Tab 是"资产 + 凭证"语义集中地 |

#### v2.0 架构调整(2 项 · 新增)

| # | 决策点 | 结论 | 理由 |
|---|--------|------|------|
| 14 | **UI 主视图与挂售入口位阶**(v2.1) | **市场单视图(买方视角),无底部 Tab;「我的」右上角入口;首页渠道分类快捷切换(全部/一口价/拍卖/租赁);挂售仅藏在「我的 → 资产详情」内** | v2.0 底部 4 Tab(市场/搜索/活动/我的)过于臃肿,搜索/活动为 P2 占位浪费导航位;v2.1 精简为单视图 + 右上角个人入口,对齐 OpenSea/Blur 移动端模式;渠道快捷切换让用户直接按成交模式筛选,比 Tab 切换更符合交易心智 |

| # | 决策点 | 结论 | 理由 |
|---|--------|------|------|

#### 运营与费用(3 项)

| # | 决策点 | 结论 | 理由 |
|---|--------|------|------|
| 11 | `GoodsMarket.listItem` 与 `FixedPriceMarket` 关系 | **E1 统一走 `FixedPriceMarket`**:`GoodsMarket.listItem` 标记为废弃,新挂单一律走渠道合约 | 避免双通道挂单造成前端展示分裂;`FixedPriceMarket` 是 `listItem` 的升级版(支持 expiry、forceClose、`TradeLedger` 记账) |
| 12 | 手续费模型(v2.1 核对) | **一口价渠道天生 0%**(`FixedPriceMarket` 合约无 `setFeeBps` 函数,货款全付卖家);拍卖 `feeBps` 默认 250(2.5%);荷兰拍 `feeBps` 默认 100(1%);租赁无手续费(租金直付出租方);各渠道 `feeBps` 由 miner 在 B 端独立配置 | 合约基准:`FixedPriceMarket` 无 feeBps 机制;`AuctionHouse`/`TimedExchange` 有 `setFeeBps`;前端展示实际到账金额 |
| 13 | miner 多签 | **所有渠道 `setEnabled` / `setFeeBps` / `forceCancel` 必须多签** | 对齐 project_memory 硬约束:防止 miner 单点作恶抽干资金 |

## 3. 用户模型与角色

### 3.1 角色矩阵

流转市场内用户只有两种动态角色:**卖家**(处置自有资产)与**买家**(购买他人资产)。同一用户在不同挂单上可能同时是两者。

| 角色 | 准入条件 | 核心动作 |
|------|---------|---------|
| 卖家 | 持有可处置的 SKU 资产(短号/商品码),`skuActive=true` | 挂单(选渠道+定价) / 撤单 / 接受出价(拍卖) |
| 买家 | 已绑定钱包(任意地址) | 浏览市场 / 出价(拍卖) / 购买(一口价) |
| miner | 多签地址 | 开关渠道 / 调整手续费 / 强制撤单 / 系统拍卖 |

### 3.2 资格与限制

| 资格 | 卖家 | 买家 |
|------|------|------|
| 钱包绑定 | 必须为已绑定地址 | 任意有效地址(同商城购买) |
| 设备指纹 | 已绑定(反女巫) | 已绑定(复用商城购买校验) |
| 黑名单校验 | 不在 `banned` 列表 | 不在 `banned` 列表 |
| 白名单(若开启) | 在 `whitelist` 内 | 在 `whitelist` 内 |
| 资产持有 | `skuOwner(skuId) == msg.sender` | 无需持有 |
| 资产状态 | `skuActive(skuId) == true` 且未被 `lockSku` | — |
| Gas 余额 | 挂单时签名地址有足够 Gas | 购买时签名地址有足够支付款 + Gas |

### 3.3 角色切换(v2.1 调整)

v2.1 精简 v2.0 的底部 4 Tab(市场/搜索/活动/我的),改为**市场单视图 + 右上角「我的」入口**。市场首页同时提供「渠道分类快捷切换」(全部/一口价/拍卖/租赁),用户可按成交模式快速筛选。挂售入口仅藏在「我的 → 资产详情」内。

```
流转市场(单视图 · 无底部 Tab)
├ 🏪 市场浏览(唯一主视图 · 买方视角)
│   ├ Header:返回 + 标题 + 🔍搜索 + 👤我的(右上角)
│   ├ 渠道分类快捷切换(全部 / 一口价 / 拍卖 / 租赁)  ← v2.1 新增
│   ├ 资产类型 chip 横滑(7 类单选筛选)
│   ├ 排序条(挂单数 + 排序方式 ▾)
│   └ 挂单网格(2 列,覆盖 7 类资产)
│
└ 👤 我的(全屏页 · 右上角入口进入)
    ├ 资产概览卡(持有数 / 在售挂单 / 累计收益 / 估值)
    ├ 我的资产(可流转)· 卡片 [挂售][详情]   ← 卖家挂售入口
    ├ 我的挂单(在售)· 卡片 [撤单][详情]

```

**角色与入口映射**:

| 角色 | 入口位置 | 触发动作 |
|------|---------|---------|
| 买家(默认) | 市场浏览(唯一视图) | 渠道快捷切换 + 资产类型筛选 + 抽屉二级筛选 + 进入详情页购买/出价/承租 |
| 卖家 | 右上角「我的」→ 我的资产 → [挂售] | 选资产 → 选渠道(一口价/拍卖/租赁)→ 填参数 → PIN 签名上链 |
| 撤单方 | 我的 → 我的挂单 → [撤单] | 选挂单 → 二次确认 → 链上撤单 |
| 出租方 | 我的 → 我的出租 → [结束租赁] | 选租赁 → `endRental`(仅出租方/miner 可提前终止,租客只能到期后调) |

> **设计要点**:市场单视图无底部 Tab,减少导航层级;渠道分类快捷切换让买家按成交模式筛选(一口价直购/拍卖竞价/租赁使用权),比 Tab 切换更贴合交易心智;挂售按钮**仅出现在「我的 → 我的资产」卡片上**,不在市场视图暴露。

## 4. 资产模型

### 4.1 统一 SKU 资产抽象(v2.0 扩展 7 类)

流转市场在前端展示层不区分短号与商品码,统一抽象为 `MarketAsset`。v2.0 将 `assetType` 从二元(`short_number` / `goods_code`)扩展为 7 类细分品类,对应顶部 chip 一级筛选与卡片视觉差异:

```typescript
type MarketAsset = {
  skuId: string;            // bytes32,短号=keccak256(number),商品码=codeId
  registry: string;         // 资产合约地址(ShortNumRegistry 或 GoodsMarket)
  assetType: AssetType;     // v2.0:7 类细分品类
  ownerAddress: string;     // 当前所有者
  
  // 短号专属
  shortNumber?: {
    number: string;         // 明文号码(脱敏可选)
    network: string;        // 所属链
    premiumType?: string;   // 豹子/顺子/吉尾号...
    premiumRate?: number;   // 倍率
  };
  
  // 商品码专属
  goodsCode?: {
    productId: number;
    productName: string;
    productImage?: string;
    isSecret: boolean;      // 保密商品
    codeHash?: string;      // 保密商品展示哈希
  };
  
  // 共有元数据
  acquiredAt: number;
  acquisitionMethod: 'primary_buy' | 'transfer_in' | 'gift_in' | 'resale_in' | 'rental_end';
};

// v2.0 资产品类枚举(7 类,对齐原型顶部 chip)
type AssetType =
  | 'short_premium'    // 💎 靓号短号(豹子/顺子/吉尾号等)
  | 'short_free'       // 🎁 免费号短号(10-12位无靓号特征)
  | 'goods_real'       // 🛒 实物商品码(硬件钥匙等)
  | 'goods_virtual'    // 🎫 虚拟兑换码(会员卡/兑换券)
  | 'goods_service'    // 🛎️ 服务包码(咨询/服务时长)
  | 'goods_secret'     // 🔒 保密商品码(链下脱敏展示)
  | 'short_combo';     // (预留)组合号包
```

| 免费号短号 | `gradient-free` | 🎁 | 🎁 免费号 | 一口价 / 赠送 |
| 实物商品码 | `gradient-goods` | 🛒 | 🛒 实物 | 一口价 / 赠送 |
| 虚拟兑换码 | `gradient-virtual` | 🎫 | 🎫 虚拟 | 一口价 / 拍卖 / 赠送 |
| 服务包码 | `gradient-service` | 🛎️ | 🛎️ 服务 | 一口价 / 赠送 |
| 保密商品码 | `gradient-secret` | 🔒 | 🔒 保密 | 一口价 / 拍卖 / 赠送(脱敏展示) |

### 4.2 资产可处置性判定(v2.1 核对)

并非所有持有资产都可进入流转市场,前端需在挂单入口预先过滤。**`lockSku` 是跨渠道锁**:一旦在任一渠道(一口价/拍卖/租赁/荷兰拍)挂单,该 SKU 即被锁定,无法同时在另一渠道再挂(合约层 `lockSku` 防双挂/并发转移)。

| 资产状态 | 可挂售 | 可拍卖 | 可租赁 | 可赠送 | 原因 |
|---------|--------|--------|--------|--------|------|
| 短号 - 已绑定(bound) | ✅ | ✅ | ✅ | ✅ | v2.1 放开短号租赁(ERC-4907 使用权分离,所有权不动) |
| 短号 - 转移中(transferring) | ❌ | ❌ | ❌ | ❌ | 已被 `lockSku` 锁定 |
| 短号 - 已挂售(listed) | ❌ | ❌ | ❌ | ❌ | 同上,需先撤单解锁 |
| 商品码 - 可售(codeStatus=1) | ❌ | ❌ | ❌ | ❌ | 库存码未售出,不可二手流转 |
| 商品码 - 已售(codeStatus=2) | ✅ | ✅ | ✅ | ✅ | 用户持有的码,完整流转能力 |
| 商品码 - 已退(codeStatus=3) | ❌ | ❌ | ❌ | ❌ | 永久作废,不可二次流转 |
| 商品码 - 已被锁定(任一渠道 active) | ❌ | ❌ | ❌ | ❌ | 跨渠道锁,需先撤单/结束租赁解锁 |
| 保密商品码 | ✅ | ✅ | ✅ | ✅ | 但列表展示脱敏 |
| 短号 - 已出租(exclusive=true) | ❌ | ❌ | ❌ | ❌ | 独占租赁 lockSku,需先 endRental 解锁 |
| 短号 - 已出租(exclusive=false) | ✅ | ✅ | ❌ | ✅ | 非独占租赁不锁,可同时挂售(但需提示租客) |

### 4.3 资产-渠道适配矩阵(v2.1 调整)

不同资产类型在不同渠道下的适配性(v2.1 租赁从 P3 提前到 P1,拍卖从 P2 提前到 P1):

| 资产类型 | 一口价(P1) | 拍卖(P1) | 租赁(P1) | 荷兰拍(P3) | 赠送(独立入口) |
|---------|----------|---------|---------|-----------|--------------|
| 靓号短号 | ✅ 主渠道 | ✅ 推荐高价靓号 | ✅ 可租(使用权) | ⚠️ 可选 | ✅ |
| 免费号短号 | ✅ | ⚠️ 不推荐(低价) | ✅ 可租 | ❌ | ✅ |
| 实物商品码 | ✅ | ⚠️ 不推荐 | ⚠️ 可选(需线下交付) | ⚠️ | ✅(实物商品码通常消费即销毁) |
| 虚拟商品码(兑换码) | ✅ | ✅ 限量版推荐 | ✅ 推荐(使用权分离) | ⚠️ | ✅ |
| 服务包码 | ✅ | ❌ | ✅ 推荐(按时长) | ❌ | ✅ |
| 保密商品码 | ✅ | ✅ | ⚠️ 可选 | ⚠️ | ✅ |

> 矩阵中"⚠️ 可选"表示合约支持但产品层不主推,用户仍可自行选择;"❌"表示产品层禁止入口暴露。

## 5. 渠道矩阵与产品设计

### 5.1 渠道总览(7 个,本方案 P1 覆盖 3 个 · v2.1)

| channelId | 渠道 | 合约 | P 级 | 本方案是否接入 | 产品语义 |
|---|---|---|---|---|---|
| 0 | PRIMARY 一级购买 | GoodsMarket/ShortNumRegistry 内置 | P1 | ❌(在商城/短号中心) | 一级发行,不属于流转市场 |
| 1 | Gift 赠送 | `GiftChannel` | P1 | ⚠️(订单中心可见,无市场浏览/无挂单弹窗) | 即时过户,非市场挂单;入口在短号中心/商品详情页 |
| 2 | FixedPrice 一口价 | `FixedPriceMarket` | P1 | ✅ | **流转市场主渠道**(天生 0% 手续费) |
| 3 | Auction 拍卖 | `AuctionHouse` | P1 | ✅ | 高价值资产竞价(feeBps 默认 250) |
| 4 | TimedExchange 荷兰拍 | `TimedExchange` | P3 | ✅(预留) | 线性降价清仓(feeBps 默认 100) |
| 5 | Rental 租赁 | `RentalChannel` | P1 | ✅ | **ERC-4907 使用权分离**(v2.1 提前至 P1) |
| 6 | Mining 挖矿 | `MiningClaim` | P3 | ❌ | 集邮挖矿,非流转 |
| 7 | Fractional 碎片化 | — | — | ❌ | 合规风险,暂不启动 |

### 5.2 渠道一:一口价(P1 · 主渠道)

#### 5.2.1 核心机制

- **合约**:`FixedPriceMarket`(channelId=2)
- **定价**:卖家自定固定价,支持指定支付币种
- **货款流向**:`transferFrom(buyer → seller)` 直付,合约不托管
- **过期**:卖家可设 `expiry`(0=永久)
- **撤单**:卖家随时撤,或 miner `forceCloseListing`
- **手续费**:**无**(货款全付卖家)— 这是与 `GoodsMarket.listItem`(收 `resaleFeeBps`)的差异点,需要 miner 决策是否给 `FixedPriceMarket` 加手续费(见决策 #12)

#### 5.2.2 用户流程

**卖家挂单**:
```
我的持有 → 选择可处置资产 → [挂售] → 选择渠道(一口价)
  → 挂单表单:
    ├ 资产信息(只读,展示 SKU 元数据)
    ├ 收款币种(下拉,从合约支持的支付币种中选)
    ├ 挂售价格(数字输入,带建议价提示)
    ├ 过期时间(可选:7天/30天/永久)
    └ 手续费提示(显示当前 feeBps 与预计到账)
  → PIN 码签名 → 链上 `listSku` → 挂单进入市场浏览
```

**买家购买**:
```
市场浏览 → 点击挂单卡 → 挂单详情页
  → 展示:资产元数据 + 卖家信息(短地址) + 价格 + 剩余有效期
  → [立即购买] → 弹起支付确认(支付币种 + 金额 + Gas)
  → PIN 码签名 → 链上 `buyListed` → 资产过户 + 货款直付卖家
```

**卖家撤单**:
```
我的挂单 → 选择挂单 → [撤单] → 二次确认 → 链上 `cancelListing` → 资产解锁回持有
```

#### 5.2.3 边界规则

| 规则 | 说明 |
|------|------|
| 同一 SKU 只能挂一单 | `lockSku` 防并发,合约层强制 |
| 挂单中资产不可直转 | 同上,`skuActive` 在锁定期间为 false |
| 挂单价格不可改 | 撤单后重新挂;不支持改价(合约无此方法) |
| 过期后自动失效 | 链下过滤过期挂单,买家不可购买;卖家需主动撤单解锁 |
| 跨网络短号拦截 | `ShortNumRegistry.channelTransfer` 内校验买卖家是否同网络 |

### 5.3 渠道二:拍卖(P1 · 高价值资产 · v2.1 提前)

#### 5.3.1 核心机制

- **合约**:`AuctionHouse`(channelId=3)
- **定价**:起拍价 + 底价(可选),英式竞价,出价最高者得
- **货款流向**:出价时 `transferFrom(bidder → 合约)` 托管;结算时合约 → 卖家(扣 `feeBps`) + treasury(收手续费)
- **超时**:到期后任何人可调 `settle` 结算
- **撤拍**:仅无出价时卖家可撤;有出价后只能等结算或 miner `forceCancel`
- **手续费**:默认 `feeBps=250`(2.5%),miner 可调
- **系统拍卖**:miner 可代 treasury 挂拍(`listSystemAuction`),用于官方资产处置

#### 5.3.2 用户流程

**卖家挂拍**:
```
我的持有 → 选择资产 → [挂售] → 选择渠道(拍卖)
  → 挂拍表单:
    ├ 资产信息(只读)
    ├ 收款币种
    ├ 起拍价(必填,>0)
    ├ 底价(可选,0=无底价;设底价则未达底价时流拍)
    ├ 拍卖时长(下拉:1天/3天/7天,或自定义)
    └ 手续费提示
  → PIN 码签名 → 链上 `listAuction` → 资产锁定 + 挂拍进入市场
```

**买家出价**:
```
市场浏览 → 切换到拍卖 Tab → 点击拍卖卡 → 拍卖详情页
  → 展示:资产元数据 + 起拍价 + 当前最高出价 + 剩余时间 + 出价历史
  → 出价输入(必须 > 当前最高出价且 ≥ 起拍价)
  → [确认出价] → 弹起支付确认(全额托管) → PIN 码签名 → 链上 `bid`
  → 若有更高出价:前一最高出价者立即收到退款(transfer 失败则挂起 `pendingRefunds`,用户可 `withdrawRefund`)
```

**结算**:
```
拍卖到期 → 任何人点击 [结算] → 链上 `settle`
  ├ 有出价且达底价:SKU 过户给最高出价者 + 货款分配(扣费→卖家,手续费→treasury)
  ├ 有出价但未达底价:退款给最高出价者,SKU 保留给卖家
  └ 无出价:流拍,SKU 保留给卖家
```

**卖家撤拍**:
```
我的挂单 → 选择拍卖 → [撤拍](仅无出价时可见) → 链上 `cancelAuction`
```

#### 5.3.3 边界规则

| 规则 | 说明 |
|------|------|
| 出价托管 | 出价金额全额入合约,非最高出价者立即退款 |
| 退款失败兜底 | `pendingRefunds` 记录,用户可主动 `withdrawRefund` |
| 流拍处理 | 无出价或未达底价,SKU 自动解锁回卖家 |
| 超期未结算 | 任何人可调 `settle`,不依赖卖家在线 |
| 强制撤拍 | miner `forceCancel` 用于争议处理,自动退款最高出价者 |

### 5.4 渠道三:荷兰拍/线性定价(P3 · 预留)

#### 5.4.1 核心机制

- **合约**:`TimedExchange`(channelId=4)
- **定价**:`startPrice` 线性衰减到 `endPrice`,按 `priceAt(now)` 实时计算
  - `endPrice < startPrice` = 荷兰拍(降价)
  - `endPrice == startPrice` = 固定价(等同一口价,但不建议用此渠道)
- **货款流向**:买家付款入合约,合约立即转给卖家(扣 `feeBps`)
- **过期**:`deadline` 到期后挂单失效,不可购买,需撤单解锁
- **手续费**:默认 `feeBps=100`(1%)

#### 5.4.2 适用场景

- **清仓场景**:卖家急于出手,愿以时间换成交,价格从高到低让市场自寻均衡点
- **限量商品码**:虚拟限量兑换码,卖家不知市场接受价,用荷兰拍发现价格

#### 5.4.3 产品流程(简)

与一口价类似,差异在挂单表单需填 `startPrice` 和 `endPrice`,且买家看到的是动态实时价(前端按 `priceAt(now)` 实时计算展示)。

### 5.5 渠道四:租赁(P1 · ERC-4907 使用权分离 · v2.1 提前)

#### 5.5.1 核心机制

- **合约**:`RentalChannel`(channelId=5,ERC-4907 语义)
- **本质**:**只转使用权(`userOf`/`userExpires`),不转所有权**;所有权保留在出租方
- **定价**:按周期定价,`totalRent = pricePerPeriod × units`
- **货款流向**:`transferFrom(tenant → owner)` 直付,合约不托管
- **独占模式**:`exclusive=true` 时 `lockSku`(防止出租期间所有人转移);`exclusive=false` 时出租方仍可转移所有权(但需提示租客)
- **到期清理**:任何人可调 `reclaimExpired(skuId)` 清除过期使用权(链下 keeper 可调)
- **手续费**:**无**(租金全付出租方)
- **提前终止**:`endRental` 仅出租方/miner 可调;租客只能到期后调

#### 5.5.2 合约函数映射

| 产品动作 | 合约函数 | 谁可调 | 参数 |
|---------|---------|--------|------|
| 出租 | `rent()` | 出租方(SKU 持有者) | registry, skuId, tenant, payToken, pricePerPeriod, period, units, exclusive |
| 结束租赁 | `endRental()` | 出租方/miner(租客仅到期后) | rentalId |
| 清理过期 | `reclaimExpired()` | 任何人 | skuId |
| 查使用权 | `userOf(skuId)` | view | — |
| 查到期 | `userExpires(skuId)` | view | — |

#### 5.5.3 用户流程

**出租方挂租**:
```
我的资产 → 选择可出租资产 → [挂售] → 选择渠道(租赁)
  → 挂租表单:
    ├ 资产信息(只读,展示 SKU 元数据)
    ├ 租客地址(tenant,需手动填或扫码)
    ├ 收款币种(payToken)
    ├ 每周期租金(pricePerPeriod)
    ├ 周期长度(period:如 1天=86400 / 1小时=3600)
    ├ 购买周期数(units:租几期)
    ├ 独占模式(exclusive:是/否,默认是)
    └ 费用提示(无手续费,租金直付出租方)
  → PIN 码签名 → 链上 `rent()` → 资产(若独占)锁定 + 使用权设置
  → 出租方收到 totalRent 直付
```

> **注意**:当前合约 `rent()` 要求出租方调用并指定 tenant,即出租方需预先知道租客地址。产品层有两种模式:
> - **定向出租**:出租方直接填租客地址(类似赠送,适合熟人/私下协商)
> - **市场挂租(P1 简化)**:出租方挂租后,租客在市场浏览看到,点击「承租」→ 前端组装 `rent()` 交易(租客签名 approve + 调用,或出租方预授权)。P1 先做定向出租模式,市场挂租待合约层扩展(或前端用前端组装方式实现)。

**承租方承租(定向模式)**:
```
出租方发起 rent() → 租客需预先 approve payToken 给出租方
→ 出租方调 rent(registry, skuId, tenant=租客, payToken, pricePerPeriod, period, units, exclusive)
→ 合约:transferFrom(租客 → 出租方, totalRent) + 设置 userOf/userExpires
→ 租客获得使用权(userOf=租客, userExpires=到期时间)
```

**结束租赁**:
```
我的出租 → 选择租赁 → [结束租赁]
  ├ 到期后:任何人可调 reclaimExpired 清理使用权(独占模式自动 unlockSku)
  └ 提前终止:出租方/miner 调 endRental(租客不可提前终止)
```

#### 5.5.4 边界规则

| 规则 | 说明 |
|------|------|
| 使用权 ≠ 所有权 | 租客只有使用权,不可处置(不可挂售/拍卖/赠送) |
| 独占锁定 | `exclusive=true` 时 lockSku,出租方也不可转移所有权 |
| 非独占 | `exclusive=false` 时出租方仍可转移所有权,但需提示租客使用中断风险 |
| 租客不可提前退 | `endRental` 租客仅到期后可调;提前终止需出租方/miner |
| 到期清理 | `reclaimExpired` 任何人可调,链下 keeper 定时清理 |
| 无手续费 | 租金全付出租方,合约不抽成 |

#### 5.5.5 适用场景

| 资产类型 | 租赁适用性 | 场景 |
|---------|----------|------|
| 虚拟商品码(兑换码) | ✅ 推荐 | 会员卡/服务订阅的临时使用权 |
| 服务包码 | ✅ 推荐 | 按时长计费(咨询时长/服务时长) |
| 靓号短号 | ✅ 可租 | 临时使用某靓号(使用权,所有权不动) |
| 实物商品码 | ⚠️ 可选 | 需线下交付配合 |
| 保密商品码 | ⚠️ 可选 | 需脱敏处理租客可见信息 |

### 5.6 渠道五:赠送(独立入口,记录可见)

#### 5.6.1 定位

赠送(`GiftChannel`,channelId=1)是"处置"但不属于"市场交易",因此:
- **不在流转市场暴露挂单入口**:赠送是定向行为,无需市场浏览
- **入口保留在原位置**:短号赠送在短号中心,商品码赠送在持有详情页
- **订单中心可见赠送记录**:作为处置历史的一部分展示

#### 5.6.2 有偿赠送 vs 无偿赠送

| 模式 | 调用方 | 费用 | 场景 |
|------|--------|------|------|
| 有偿赠送 | 号主 | 手续费(`feeConfig`)→ treasury | 用户付费将短号送给他人 |
| 系统批量赠送 | miner / 授权活动合约 | 无 | 官方活动批量发码 |

**关键约束**(v2.1 补强 forceSettle/forceCancel/withdrawRefund 归属):

| 函数 | 谁可调 | 触发条件 | 归属入口 |
|------|--------|---------|---------|
| `bid(auctionId, amount)` | 任意买家 | 出价 > 当前最高价且 ≥ 起拍价 | 弹窗内「确认出价」按钮 |

| `cancelAuction(auctionId)` | **卖家** | 仅在**无出价**时可撤;有出价后只能等结算或 miner forceCancel | 拍卖详情页「撤拍」按钮(无出价时可见,有出价时禁用并提示) |

**结算分支逻辑**:

| 结算场景 | settle 行为 | 结果 |
|---------|------------|------|
| 有出价且达底价 | SKU 过户给最高出价者 + 货款分配(扣 `feeBps=250` → 卖家,手续费 → treasury) | 成交 |
| 有出价但未达底价 | 退款给最高出价者(自动 transfer,失败挂 `pendingRefunds`),SKU 保留给卖家 | 流拍 |
| 无出价 | 流拍,SKU 解锁回卖家(无需退款) | 流拍 |

**前端交互要点**:
- 出价必须 > 当前最高价(前端校验 ≥ 当前最高 + 1)
- 出价金额托管至 `AuctionHouse` 合约,被超越后**自动** transfer 退回前一最高出价者;若 transfer 失败则挂 `pendingRefunds`,用户需主动 `withdrawRefund`
- 达底价才成交,底价对买家隐藏(仅卖家可见)
- 拍卖结束后任何人可点击 `settle` 结算(C 端拍卖详情页有「结算」按钮,超期未结算时高亮提示「⏰ 拍卖已到期,点击结算」)
- 系统拍卖(`listSystemAuction`):miner 代 treasury 挂拍官方资产,C 端无创建入口,仅可见可竞拍

## 7. 状态机

### 7.1 资产状态机(流转市场视角)

流转市场不重新定义资产状态机,而是基于合约层 `lockSku` / `channelTransfer` 派生前端状态:

```
                    [持有(bound/codeStatus=2)]
                              │
            ┌─────────────────┼─────────────────┐
            │                 │                 │
       [挂售一口价]       [挂拍拍卖]        [挂租 P1]
            │                 │                 │
            ▼                 ▼                 ▼
      [listed_fixed]    [listed_auction]   [rented]
            │                 │                 │
       ┌────┴────┐       ┌────┴────┐           │
       │         │       │         │           │
   [被购买]  [撤单]   [成交]   [撤拍/流拍]   [到期/结束]
       │         │       │         │           │
       ▼         ▼       ▼         ▼           ▼
   [bound    [bound   [bound   [bound       [bound
    新主]     原主]    新主]    原主]        原主]
```

### 7.2 挂单状态机(跨渠道)

| 渠道 | 状态枚举 | 流转 |
|------|---------|------|
| 一口价 | `listed` → `sold` / `cancelled` / `expired` | listed→sold(被买)/ listed→cancelled(卖家撤)/ listed→expired(超期,链下过滤) |
| 拍卖 | `auction_active` → `auction_settled`(成交/流拍)/ `auction_cancelled` | active→settled(结算)/ active→cancelled(撤拍) |
| 荷兰拍 | `timed_active` → `timed_filled` / `timed_cancelled` / `timed_expired` | active→filled(被买)/ active→cancelled(撤)/ active→expired(超期,需撤单解锁) |
| 租赁 | `rental_active` → `rental_ended` | active→ended(到期/主动结束) |

### 7.3 订单状态机(TradeLedger 视角)

所有渠道成交在 `TradeLedger` 中以 `TradeOrder` 记录,状态:

```
[order_recorded] ──[reversal]──→ [order_reversed]
```

- `recorded`:正常成交
- `reversed`:有冲销单关联(退货/撤销)

前端订单中心状态:
- **已成交**:无冲销单
- **已撤销**:有冲销单(如租赁退款、争议撤销)
- **进行中**(仅租赁):租期未到

## 9. 风控与边界

### 9.1 资产层风控

| 风险 | 应对 |
|------|------|
| 跨网络短号误转 | `ShortNumRegistry.channelTransfer` 内校验买卖家同网络,合约层拦截 |
| 保密商品码泄露 | 流转市场列表展示脱敏(哈希 + 商品名),明文 codeId 不上链,链下映射 |
| 退货后码再流通 | `codeStatus=3` 的码在前端"我的持有"中标记"已作废",不显示挂售按钮 |
| 已锁定资产重复挂单 | `lockSku` 合约层强制,前端在挂单入口预检 `skuActive` |
| 挂单价格异常(过高/过低) | 前端警告提示(非阻断),如"价格远高于历史均价,确认是否合理" |

### 9.2 交易层风控

| 风险 | 应对 |
|------|------|
| 拍卖出价后不结算 | 任何人可调 `settle`,不依赖卖家在线;超期未结算 miner 可 `forceSettle` |
| 拍卖退款失败 | `pendingRefunds` 兜底,用户主动 `withdrawRefund` |
| 荷兰拍超期未撤 | `forceCancel` 由 miner 处理,卖家不主动撤单时资产仍锁定 |
| 租赁到期未清理 | 任何人可调 `reclaimExpired`,链下 keeper 定时清理 |
| 货款支付失败 | `transferFrom` revert 整单,合约原子性保证 |
| 重放攻击 | `orderId` 含 `block.chainid` + `nonce`,跨链不通用 |

### 9.3 运营层风控

| 风险 | 应对 |
|------|------|
| miner 单点作恶 | 所有 `setEnabled`/`setFeeBps`/`forceCancel` 多签,对齐 project_memory 硬约束 |
| 渠道被滥用洗钱 | 黑名单机制(每个渠道独立 `banned`?),建议复用 GoodsMarket 的黑白名单 |
| 系统拍卖资产来源不明 | `listSystemAuction` 仅 miner 可调,且资产必须先在 treasury 名下 |
| 异常手续费 | `feeBps` 上限 2000(20%),合约层强制 |

### 9.4 用户体验风控

| 风险 | 应对 |
|------|------|
| 赠错地址 | 赠送二次确认 + 地址格式校验(沿用短号中心规则) |
| Gas 不足 | 交易前检查余额,不足时提示 |
| 链上延迟 | `pending` 状态锁定按钮,展示进度 |
| 价格波动(拍卖) | 出价时显示当前最高价 + 建议出价,避免盲目出价 |
| 挂单遗忘 | "我的挂单"顶部提醒超期挂单,引导撤单或续挂 |

## 11. 链下服务新增清单

| 服务 | 职责 | 优先级 |
|------|------|--------|
| 流转市场 Indexer | 监听各渠道合约事件,派生聚合索引(在售挂单/用户挂单/订单历史/资产流转历史) | P1 |
| 价格建议服务 | 基于历史成交 + 在售均价 + 业务规则,计算挂单建议价 | P2 |
| 跨渠道订单中心 API | 提供前端订单聚合查询(跨渠道、分页、筛选) | P1 |
| 资产可处置性预检 | 链下缓存资产状态,挂单入口预检可处置性(减少链上调用) | P1 |
| 过期挂单清理 keeper | 定时扫描过期挂单,提醒卖家撤单(荷兰拍/一口价) | P2 |
| 租赁到期清理 keeper | 定时调 `reclaimExpired`,清理过期使用权 | P3 |

**架构原则**:Indexer/API 只读链上数据派生索引,不涉及用户私钥/资金,与 Node"云端无状态"原则不冲突。

## 15. 总结

### 15.1 核心判断

流转市场是 Node 体系内基于 SKU 渠道化合约基建的统一二手资产处置中心。它不重新发明合约,而是**聚合已设计的 7 个渠道合约**(本方案覆盖 4 个:P1 一口价、P2 拍卖、P3 荷兰拍+租赁),在前端提供统一入口与跨渠道订单管理。

### 15.2 三大设计动作

1. **统一入口**:流转市场挂在身份 Tab(Tab 2)下,聚合短号 + 商品码两类资产的处置,避免按资产类型分散
2. **多渠道并存**:一口价(P1)、拍卖(P2)、荷兰拍(P3)、租赁(P3)四种渠道并存,用户可选最契合资产的处置方式
3. **统一台账**:所有成交写入 `TradeLedger`,链下派生跨渠道订单中心,用户在一个页面看到自己所有渠道的挂单与历史

### 15.3 不变的核心

- **合约基建完全沿用**:`ISkuRegistry` + `TradeLedger` + 7 渠道合约,本方案不重新设计合约
- **奖励铁律**:流转市场所有渠道流水不纳入代理奖励分润(对齐合约层铁律)
- **归因无关**:流转市场不触发 `bindOnPurchase`,与 Tab 3 团队关系解耦
- **设备校验**:复用 Tab 2 保险库的 `DeviceRegistry.isBoundAddress`,反女巫

### 15.4 落地路径

P1 跑通"一口价跨资产流转 + 跨渠道订单中心 + 短号/商城入口打通",验证用户能挂售短号/商品码并被其他用户购买,成交写入 TradeLedger;P2 叠加拍卖与价格建议;P3 叠加荷兰拍与租赁。
