## 一、设计目标

### 1.1 这份蓝图要解决什么

当前产品已完成 v1.0 定版(5 Tab + B 端),但存在三个问题:
1. **模块关联散落各处**:每个模块的 PRD/方案文档独立存在,缺乏全局视角的关联图
2. **商业逻辑隐性化**:资金流、价值流、关系流的闭环散落在合约代码中,非技术人员难以理解
3. **未来演进缺锚点**:代销体系、资产 token 化、应用中心抽成等规划能力缺乏架构层面的预留

本蓝图目标:**一张图说清 Node 产品的商业全貌 + 模块关联 + 演进路径**。

### 1.2 设计原则

| 原则 | 说明 |
|---|---|
| 商业优先 | 先讲商业逻辑(为什么这样做),再讲模块结构(怎么做的) |
| 关联清晰 | 每个模块的输入/输出/依赖必须显式标注 |
| 分层解耦 | 按商业职能分层,不按 Tab 分层(Tab 是用户视角,分层是架构视角) |
| 演进留白 | 已实现/开发中/规划中三层共存,规划能力预留接口 |

### 2.3 三大铁律(不可违背)

| 铁律 | 商业意义 |
|---|---|
| 私钥永不上链/上云 | 资产主权归用户,平台不托管,合规免责 |

| 地址即身份 | 算钱/绑定/鉴权只信链上地址,Web2 凭证仅辅助 |

## 三、六大商业引擎

> 产品手册定义的六大引擎,是 Node 商业闭环的核心驱动力。

| 引擎 | 所属职能 | 核心机制 | 商业目的 | 状态 |
|---|---|---|---|---|
| **引擎一·统一商品池** | 交易 | 官方统一上架、全平台同价同库存 | 破除层级割裂,统一发行口径 | ✅ |
| **引擎二·永久关系绑定** | 关系 | 链上 set-once + 5 渠道归因 | 关系资产化,防跳号洗下级 | ✅ |
| **引擎三·级差返利** | 交易+关系 | 3层分润 + 10级等级 + 动态压缩 | 激励推广+培养团队,防空团长 | ✅ |
| **引擎四·双积分体系** | 关系 | 个人积分(防白嫖)+ 团队积分(防空团长) | 双轨驱动,筛选真代理 | ✅ |
| **引擎五·流转市场** | 交易 | 一口价/拍卖/赠送(租赁规划中) | 资产可流通,提升持有意愿 | ✅ |
| **引擎六·应用中心** | 独立 | CPS抽成 + 上架费,不参与团队归因 | 流量变现,独立利润中心 | ✅ |

## 四、分层架构(架构视角)

> 按**商业职能分层**,非按 Tab 分层。Tab 是用户视角,分层是架构视角。

```
┌─────────────────────────────────────────────────────────────┐
│  L7 应用层 │  应用中心(第三方应用分发+抽成)              │ 独立利润中心  │
├─────────────────────────────────────────────────────────────┤
│  L6 身份层 │  DID通行证 + 福利特权 + 保险库L1            │ 信任根基+激励  │
├─────────────────────────────────────────────────────────────┤
│  L5 流转层 │  一口价/拍卖/赠送 + TradeLedger台账        │ 资产二级处置   │
├─────────────────────────────────────────────────────────────┤
│  L4 返利层 │  AgentReward + AgentLevel + AgentPoints     │ 分润+升级燃料  │
│            │  + RewardClaim                              │               │
├─────────────────────────────────────────────────────────────┤
│  L3 资产层 │  GoodsMarket + ISkuRegistry + 短号中心      │ 商品发行+资产化│
├─────────────────────────────────────────────────────────────┤
│  L2 关系层 │  ReferralRegistry(永久上下级)+ DeviceRegistry │ 关系网络+反女巫│
├─────────────────────────────────────────────────────────────┤
│  L1 基础层 │  自管钱包 + 代币体系(RC/USDRs/HRCs/RSTs)+ Swap │ 资产基座+获客  │
└─────────────────────────────────────────────────────────────┘
```

### 4.1 分层依赖规则

- **上层依赖下层,下层不感知上层**(单向依赖)
- L2 关系层是分水岭:L1+L2 构成"信任基座",L3-L5 构成"商业引擎",L6-L7 构成"生态扩展"
- L7 应用中心**独立于 L2-L6**,不参与关系与分润(合规防火墙)

## 五、三大飞轮(商业动力学)

### 5.1 飞轮全景

```
        ┌─────────────────────────────────────────────┐
        │              Node 商业飞轮                   │
        │                                              │
        │   ┌──────────┐    ┌──────────┐   ┌──────────┐│
        │   │ 交易飞轮  │───→│ 关系飞轮  │──→│ 资产飞轮  ││
        │   │ 购买→返利 │    │绑定→发展 │   │购买→持有 ││
        │   │ →复投    │←───│ →升级    │←──│→流转→增值││
        │   └──────────┘    └──────────┘   └──────────┘│
        │        ↑               ↑              ↑       │
        │        └───────────────┼──────────────┘       │
        │                   设备指纹                    │
        │                   (信任根基)                   │
        └─────────────────────────────────────────────┘
```

### 5.2 飞轮详解

| 飞轮 | 输入 | 核心动作 | 输出 | 与其他飞轮的关联 |
|---|---|---|---|---|
| **交易飞轮** | 用户购买商品 | 成交→级差返利→上线获得佣金→复投 | 资金流动+积分累加 | 返利驱动关系飞轮;购买产生资产驱动资产飞轮 |
| **关系飞轮** | 用户绑定上下级 | 绑定→发展下级→团队积分累加→升级 | 等级提升+返利比例提升 | 等级提升放大交易飞轮返利;关系网络扩大资产飞轮流通 |
| **资产飞轮** | 商品发货资产化 | 购买→持有→流转市场处置→增值变现 | 资产流动性+用户粘性 | 资产流转产生二级市场;持有资产提升等级门槛达标率 |

### 5.3 飞轮启动顺序

```
设备指纹绑定(L2) → 团队关系绑定(L2) → 首次购买(L3)
→ 返利触发(L4) → 积分累加(L4) → 资产化(L3)
→ 流转处置(L5) → 升级(L4) → 福利领取(L6)
→ 应用使用(L7) → DID授权(L6)
```

## 六、核心商业闭环

### 6.1 资金流闭环(用户付款后资金去向)

```
用户付款(USDRs/RC/HRCs)
    │
    ├─① 货款 → treasury(平台/商家收入)
    │
    ├─② 级差返利 → 沿上线链3层,按rebateBps[rank][layer]分配
    │   ├─ L1上线 → RewardClaim额度(冻结7/14/30天)
    │   ├─ L2上线 → RewardClaim额度(冻结)
    │   └─ L3上线 → RewardClaim额度(冻结)
    │   (compression:未达标上线跳过,名额上卷)
    │
    ├─③ 买家自身奖励 → rewards[]逐条写入买家RewardClaim
    │
    ├─④ 积分mint → AgentPoints.mint(个人积分,Soulbound)
    │              AgentLevel.recordPoints(团队积分,沿E链累加)
    │
    └─⑤ 手续费 → 各渠道独立(一级商城在货款内,拍卖2.5%等)
```

**退款回滚机制(三重防护)**:
1. 前置硬条件:退货前必须先 returnReward 退回奖励
2. 逐层 revoke:AgentReward 沿链撤销未领取奖励
3. 自动抵扣:已领取的从后续未领取佣金自动抵扣

**关键铁律**:退货只退钱,**不解除关系**(保护归因链路可信度)。

### 6.2 价值流闭环(用户行为产生的价值)

```
用户购买商品
    │
    ├─ 资产获得:codeId(发货后资产化,可进流转市场)
    │
    ├─ 关系强化:bindOnPurchase(未绑定则绑定到seller)
    │
    ├─ 返利分配:级差返利链(3层上线各得份额)
    │
    ├─ 积分累加:
    │   ├─ 个人积分(自己买→防白嫖)
    │   └─ 团队积分(下级买→沿E链累加→防空团长)
    │
    └─ 等级推进:积分达标→升级审核→rank提升→返利比例提升
```

### 6.3 关系流闭环(关系网络如何驱动商业)

```
设备指纹绑定(一机一包)
    ↓
团队关系绑定(5渠道归因,set-once)
    ↓
成为某人的L1/L2/L3上线
    ↓
下级购买触发返利(按rank×layer分配)
    ↓
团队积分累加(沿E链teamDepth层)
    ↓
积分达标→升级(rank 1→10)
    ↓
等级提升→返利比例提升→收益增加
    ↓
激励继续发展下级(关系网络扩张)
```

### 7.2 模块输入输出矩阵

| 模块 | 输入(依赖) | 输出(提供) | 耦合强度 |
|---|---|---|---|
| **L1 自管钱包** | 无(基座) | 钱包地址、代币余额、Swap能力 | 基础 |
| **L2 设备指纹** | L1钱包地址 | isBoundAddress校验、冷密钥 | 🔴 最高(全App闸门) |
| **L2 关系绑定** | L2设备指纹、L1钱包地址 | referrerOf(上线链)、5渠道归因 | 🔴 最高(分润依据) |
| **L3 商品发行** | L2设备指纹、L2关系绑定 | codeId资产、订单、购买事件 | 🔴 高(触发返利) |
| **L3 短号中心** | L1钱包地址、L2关系绑定 | 短号资产、转移能力 | 🟡 中 |
| **L4 级差返利** | L2关系链、L3购买事件、L4等级 | RewardClaim额度(各上线) | 🔴 最高(资金分流) |
| **L4 双积分** | L3购买事件、L2关系链 | 个人积分、团队积分、升级门槛 | 🟠 高(等级驱动) |
| **L4 等级升级** | L4积分、miner审核 | rank(1-10)、rebateBps矩阵 | 🟠 高(影响返利) |
| **L5 流转市场** | L3资产(codeId)、L1钱包 | 二级成交、TradeLedger记录 | 🟡 中(不触发返利) |
| **L6 福利特权** | L2设备指纹、L1钱包地址 | 空投/资产/互动奖励 | 🟡 中 |
| **L6 保险库** | L1钱包、设备硬件 | 安全闸门、冷密钥 | 🔴 最高(全App基座) |
| **L6 DID通行证** | L1钱包、L2设备指纹 | 签名凭证、跨应用身份 | 🟡 中 |
| **L7 应用中心** | L1钱包(可选) | 应用下载、CPS抽成 | 🟢 低(独立) |

### 7.3 关键耦合链路(最易出问题的8条)

| # | 链路 | 涉及层 | 风险 |
|---|---|---|---|
| 1 | 购买→返利 | L3→L4→L2 | 返利计算错误、compression失效 |
| 2 | 退货→撤返利 | L3→L4 | P0/P1漏洞(直写奖励不撤销) |
| 3 | 关系绑定→设备指纹 | L2→L2 | 绕过设备指纹绑定 |
| 4 | 购买即绑定 | L3→L2 | bindOnPurchase逻辑错误 |
| 5 | 升级→返利比例 | L4→L4 | rank提升后rebateBps取错 |
| 6 | 资产化→流转 | L3→L5 | 资产状态不一致 |
| 7 | 团队积分累加 | L3→L4→L2 | 沿E链累加层数错误 |
| 8 | 跨渠道锁 | L5→L5 | 重复挂单(已由lockSku解决) |

├──────────┴──────────┴──────────┴──────────────────────┤

### 8.2 USDT计价 / USDRs结算双轨制

| 维度 | USDT | USDRs |
|---|---|---|
| 角色 | 计价基准(价值锚) | 结算货币(流通) |
| 门槛 | "1000U"、"≥500 USDT"等 | 持仓门槛以USDRs计量 |
| Swap | ↔USDRs 无门槛(入金主通道) | 内部流通 |
| 商业目的 | 外部价格透明(降低决策成本) | 内部资金沉淀(锁定价值) |

### 8.3 Swap白名单分级(风控阀门)

| 等级 | 解锁能力 | 商业目的 |
|---|---|---|
| 无门槛 | RC↔USDRs、USDT↔USDRs | 获客+入金 |
| rank≥3 | HRCs Swap | 生态权益绑定等级 |
| rank≥5 或 持仓≥5000 | 大额(≥1000U) | 双轨准入防洗钱 |
| rank≥7 或 持仓≥20000 | 超大额(≥10000U) | 高净值用户通道 |

| **L6 身份层** | (Vault SDK + DID合约) | 设备指纹+签名授权 |

### 9.2 合约耦合关系图

```
GoodsMarket.buy()
    │
    ├─→ ReferralRegistry.referrerOf()  [查上线链]

    ├─→ AgentReward.onPurchase()  [触发返利]

    │
    ├─→ RewardClaim.addReward()  [直写奖励rewards[]]
    └─→ ISkuRegistry.assignCode()  [分配codeId]
```
