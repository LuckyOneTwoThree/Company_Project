## 一、产品定位

### 1.1 一句话定位

**统一商品池 + 级差返利**的 Web3 商城：所有用户共享同一商品池，购买行为触发沿上线链 N 层级差分润，等级决定返利比例。

### 1.2 三大核心决策

| 决策 | 含义 | 产品影响 |
|---|---|---|
| **仅官方上架** | 矿工统一上架商品、统一定价、统一管库存 | 无 C 端商家入驻流程 |
| **全平台统一商品池** | 所有用户看到同一商品池、同一价格 | 无代理层级商品池概念 |
| **取消代销概念** | 无代销、无 Z 价、无上下级库存调拨 | 商品详情页仅"立即购买" |

### 1.3 设计哲学

- **等级驱动**：等级是个人状态，决定返利比例，与他人无关
- **普众参与**：rank=0 也可购买，仅影响"自己作为上线时是否合格"
- **动态压缩**：上线不合格自动跳过，名额上卷，不浪费
- **公平升级**：A 升 L10 不会抬高其上线等级，必须自己达标

## 二、用户角色与状态

### 2.1 三种用户角色（C 端）

| 角色 | E 链绑定 | rank | 核心权限 | 入口限制 |
|---|---|---|---|---|
| **游客** | ❌ 未绑定 | - | 浏览 + 购买（首次购买触发归因绑定） | 无代理中心 |
| **买家** | ✅ 已绑定 | 0 | 浏览 + 购买 + 订单 + 持有码 | 无代理中心 |
| **代理** | ✅ 已绑定 | 1..10 | 买家全部 + 代理中心 + 返利 + 升级 | 全功能 |

> **矿工视角**属于后台运营系统（r9-admin），不在 C 端原型展示。

### 2.2 关键概念澄清

**等级 ≠ 层级**（极易混淆）：

| 概念 | 符号 | 范围 | 含义 | 决定 |
|---|---|---|---|---|
| **等级 rank** | L1..L10 | 个人 | 代理级别，每个人独立 | 返利比例 |
| **层级 layer** | L1/L2/L3 | 订单 | 沿上线链的深度位 | 分润深度位 |

> 关系链中 L3a 等级可以大于 L2a（兄弟节点等级倒挂），完全合法、符合设计预期。

**两种积分**：

| 积分类型 | 来源 | 用途 |
|---|---|---|
| 个人积分 | 自己购买商品 mint | L1-L2 升级门槛 |
| 团队积分 | 下级购买累加（含自己） | L3+ 升级门槛（防光杆司令） |

**双视角模型**（仅产品/研发演示用，C 端不展示）：

| 视角 | 颜色 | 含义 | 展示位置 |
|---|---|---|---|
| 🛒 购买视角 | 蓝色 | 我买东西时上线赚多少 | role-float 浮层 |
| 💰 上线视角 | 绿色 | 别人买东西我赚多少 | role-float 浮层 |

## 三、商品模型

### 3.1 商品类型分类

| 类型 | 积分 | 喂团队 | 保密 | 典型场景 |
|---|---|---|---|---|
| **实物商品** | 0 | 否 | 否 | 硬件设备 |
| **虚拟商品** | 0 | 否 | 是 | 卡密/激活码 |
| **级别服务商品** | >0 | 是 | 否 | 升级服务包 |
| **积分商品** | >0 | 否 | 否 | 纯积分包 |

### 3.2 商品定价规则

- **多币定价**：每个商品可配置多种支付币种（USDR/USDT 等）
- **统一价**：全平台同价，不分代理层级
- **数量折扣阶梯**：满 N 件享折扣（取满足条件的最高 minQty 那档，默认原价）

### 3.3 保密商品（secretCode）

- 商品级开关，开启后：
  - 链上仅存哈希，**绝不上链明文卡密**（攻击者扫描历史 calldata 无法还原）
  - 真实卡密由链下数据库管理
  - 购买后用户凭订单 refId 调链下 API 领取
- 业务场景：高价值卡密、激活码

### 3.4 直写奖励（rewards[]）

商品可配置直写奖励，给买家自身（独立于上线返利）：

| 模式 | 含义 | 示例 |
|---|---|---|
| mode 0 | 固定金额 × qty | 买硬件送 100 USDR/件 |
| mode 1 | 按成交价比例 bps | 买会员返 5% USDR |

> **配置不可单独删除**：只能 `clearRewardCfg` 清空全部，再重新配置。

## 四、核心业务流程

### 4.1 购买流程（核心）

```
用户购买商品
   │
   ├─ ① 前端校验：授权/余额/MOQ/库存
   ├─ ② 预览总价：quote(productId, qty, payToken)
   ├─ ③ PIN 码验签 → 触发链上交易
   │
   └─ 链上执行（用户无需感知）：
       ├─ 收款（transferFrom 到 GoodsMarket 合约）
       ├─ 分配唯一码（qty 个，状态：可售→已售）
       ├─ 直写奖励 → RewardClaim.addReward（买家自身）
       ├─ 升级燃料 → AgentPoints.mint + AgentLevel.recordPoints
       └─ 上线返利 → AgentReward.onPurchase（沿 E 链 N 层分润）
```

### 4.2 退货流程（含 P0 防护）

```
买家申请退货 → 矿工审核 → 退款
   │
   ├─ 前置硬条件（矿工后台校验）：
   │   ├─ 直写奖励已撤销/退回（P0 防护）
   │   └─ 级差返利已撤销/退回（P1 防护）
   │
   ├─ 退款金额（refundAmount）：
   │   ├─ 矿工输入，建议 ≤ 订单金额 1.5 倍
   │   └─ 必须多签复核（防抽干合约攻击）
   │
   └─ 退货后状态：
       ├─ 唯一码状态：已售→已退（永久作废，不可重置）
       ├─ 订单标记：returned=true
       └─ 团队积分：不扣减（需后台风控）
```

**关键规则**：
- **仅支持整单退货**，不支持部分退货
- 退货后码永久作废，无法再次销售
- teamPoints 不扣减，需后台风控识别"高退货率+高 teamPoints"异常地址

### 4.3 级差返利流程

```
购买触发 → 沿 E 链取 N 层（默认 3 层）
   │
   └─ 每层判定：
       ├─ 该层上线 rank ≥ 1 → 合格，按其自身 rank 取 rebateBps[rank][layer]
       └─ 该层上线 rank = 0 → 跳过（compression），名额上卷
```

**返利矩阵示例**（rank × layer）：

| rank | L1 返利 | L2 返利 | L3 返利 |
|---|---|---|---|
| 1 | 15.0% | 8.0% | 2.0% |
| 5 | 19.0% | 10.0% | 3.0% |
| 10 | 25.0% | 13.0% | 5.0% |

### 4.4 升级流程

```
用户申请升级 → 矿工审核 → 落等级
   │
   ├─ 申请：requestUpgrade(targetLevel)
   │   └─ 快照当前 metric（个人积分或团队积分）
   │
   ├─ 审核：miner approveUpgrade(id, enforceThreshold)
   │   └─ enforceThreshold=true 时强制校验当前 metric 是否达标
   │
   └─ 门槛基准（逐级配置）：
       ├─ L1-L2：个人积分（自己买货升级）
       └─ L3-L10：团队积分（必须带下级达标，防光杆司令）
```

### 4.5 流转市场流程

```
持有人挂单 → 买家购买 → 分账
   │
   ├─ 挂单：设置 payToken + price
   ├─ 购买：买家付款 → 手续费 → 卖家
   │   ├─ fee = price × resaleFeeBps / 10000
   │   └─ toSeller = price - fee
   └─ 唯一码所有权转移（_moveCode 3 步原子操作）
```

## 六、关键业务规则

### 6.1 角色权限矩阵

| 功能 | 游客 | 买家 | 代理 |
|---|---|---|---|
| 浏览商品池 | ✅ | ✅ | ✅ |
| 购买商品 | ✅（触发归因绑定） | ✅ | ✅ |
| 查看订单 | ✅ | ✅ | ✅ |
| 申请退货 | ✅ | ✅ | ✅ |
| 查看持有码 | ✅ | ✅ | ✅ |
| 流转市场 | ✅ | ✅ | ✅ |
| 代理中心 | ❌ | ❌ | ✅ |
| 我的返利 | ❌ | ❌ | ✅ |
| 升级管理 | ❌ | ❌ | ✅ |

### 6.2 唯一码状态机

```
0 未设 (unset) → 1 可售 (available) → 2 已售 (sold) → 3 已退 (returned)
```

**关键约束**：
- 退货后状态变 3，**永久作废**（合约无重置方法）
- 已退码无法再次导入销售
- `productCodes` 视图仅返回可售码列表

### 6.3 返利相关参数

| 参数 | 默认值 | 含义 |
|---|---|---|
| `rebateLayers` | 3 | 返利层数（硬上限 10） |
| `compression` | true | 动态压缩开关 |
| `maxCompressionSkips` | 20 | 压缩上卷步数上限（硬上限 100） |
| `minRebate` | 0 | 去尘阈值（低于不发省 gas） |
| `maxRebatePerLayer` | 0 | 单层封顶（0=不限） |
| `maxTotalPerOrder` | 0 | 整单封顶（0=不限） |

### 6.4 升级门槛基准

| 等级 | 门槛基准 | 设计意图 |
|---|---|---|
| L1-L2 | 个人积分 | 自己买货即可升级 |
| L3-L10 | 团队积分 | 必须带下级达标，防光杆司令 |

## 七、风险防护策略

### 7.1 P0 级风险（资金安全）

| 风险 | 防护策略 |
|---|---|
| **直写奖励退货不自动撤销** | 矿工后台 approveReturn 前必须先 revokeReward/returnReward 所有直写奖励，前端硬编码校验 |
| **approveReturn 抽干合约攻击** | miner 地址必须是多签钱包（Gnosis Safe 2/3），refundAmount 超阈值需第二 miner 复核 |
| **保密商品 calldata 扫描** | 链上仅存哈希，真实卡密链下管理，绝不上链明文 |

### 7.2 P1 级风险（数据一致性）

| 风险 | 防护策略 |
|---|---|
| **积分静默失败** | 后端建立异步对账任务，监听 Purchased 事件反向验证 Minted/PointsRecorded 事件，失败时告警矿工手动补发 |
| **approveReturn 不校验奖励已退回** | 矿工后台前端硬编码校验 returnedAmount ≥ amount，任一不满足禁用 approveReturn 按钮 |
| **RebateHookFailed 事件** | 仅返利未发，主交易仍成功，运营补打返利即可 |

### 7.3 P2 级风险（风控）

| 风险 | 防护策略 |
|---|---|
| **刷单升级** | teamPoints 不扣减，后台识别"高退货率+高 teamPoints"异常地址，miner 可调 minerSetLevel 降级 |
| **退货率异常** | 建立退货风控模型，限制高频退货地址 |

## 八、C 端设计原则

### 8.1 极简主义

- 商品详情页底部按钮**仅核心交易动作**：立即购买
- 无收藏、无客服、无评价等辅助功能（聚焦核心交易）
- 无代销、无 Z 价、无上下级商品池概念

### 8.2 角色信息隐藏

- C 端不展示"购买者视角/上级分佣"等内容
- 双视角内容仅保留在产品/研发演示用的 role-float 浮层
- 用户看到的只有：商品、订单、自己的返利/持有码

### 8.3 浅色主题

- 全平台浅色主题
- 信息密度优先于视觉装饰
- 卡片化布局、清晰层级

### 8.4 渐进式引导

- 游客可浏览可购买（降低参与门槛）
- 首次购买触发归因绑定（无感知）
- 代理功能仅在已绑定 rank≥1 时显示

## 九、依赖与集成

### 9.1 链上合约依赖

| 合约 | 职责 |
|---|---|
| **GoodsMarket** | 商品买卖主入口 |

### 9.2 链下依赖

| 系统 | 职责 |
|---|---|
| **链下 API** | 商品元数据、保密商品卡密管理 |
| **r9-admin 矿工后台** | 退货审核、对账告警、风控、配置 |

| **IPFS/对象存储** | 商品图片 |

### 9.3 部署后回填

部署完成后，矿工后台需配置：
- 各合约地址（GoodsMarket/AgentPoints/AgentLevel/AgentReward/RewardClaim）
- 授权链路：GoodsMarket → AgentPoints.mint + AgentLevel.recordPoints + AgentReward.onPurchase
- AgentReward.setRewarder(GoodsMarket, validUntil)
- 各 RewardClaim 实例资金补充
