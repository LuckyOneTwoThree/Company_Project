# 短号中心模块设计方案（转移·赠送·可扩展交易）

## 1. 方案背景与目标

### 1.1 背景

数字通行证短号当前作为"账号卡片下的服务能力"存在，支持免费领取和靓号购买。随着短号资产化属性增强，用户需要将短号在不同身份间转移、赠送他人，未来还可能转卖、挂售。

当前短号绑定在单个账号卡片下、以弹窗形式管理，无法承载转移/赠送等跨账号、跨用户的操作流程。需要一个**独立的短号管理中心**，以全局视角统一管理用户名下的所有短号资产。

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| 独立入口 | 在身份模块下新增"短号中心"独立入口，与 DID Pass 平行 |
| 资产化视图 | 以设备指纹钱包地址为基础，聚合展示该设备下所有地址名下的短号 |
| 转移能力 | 支持短号在自己的不同钱包地址间转移 |
| 赠送能力 | 支持短号无偿赠送给他人的钱包地址 |
| 可扩展架构 | 预留转卖、挂售的状态机和合约接口，后续可快速接入 |

### 1.3 核心设计原则

1. **短号即资产**：短号从"账号附属服务"升级为"链上资产"，具有独立的所有权属性，可转移、可处置
2. **设备指纹聚合**：短号中心以当前设备的钱包地址群为基础，自动聚合该设备管理名下所有地址的短号，无需手动切换
3. **操作与持有分离**：短号的"领取/购买"仍保留在 App 身份管理页的账号卡片下；短号中心专注于"资产管理与处置"
4. **链上确权**：转移和赠送均为链上操作，通过智能合约变更短号的所有权地址，本地 PIN 码签名确认
5. **C端极简**：严格对齐 Node 现有产品能力，不做多余功能

## 2. 模块定位与入口

### 2.1 入口位置

在身份 Tab（Tab 2）下，与"福利特权""保险库""数字身份通行证"平级，新增"短号中心"卡片入口。

```
身份 Tab
  ├── 🎁 福利特权
  ├── 🛡️ 保险库 (Vault)
  ├── 🔑 数字身份通行证 (DID Pass)
  ├── 🔢 短号中心 (Short Number Hub)   ← 新增
  └── 🔄 身份切换器
```

### 2.2 模块关系

| 维度 | App 身份管理页 · 短号服务弹窗 | 短号中心 |
|------|------|------|
| **入口** | 账号卡片 → 服务标签行 → 🔢 标签 | 身份 Tab → 短号中心卡片 |
| **视角** | 单个账号维度 | 全局资产维度（该设备所有地址） |
| **功能** | 领取免费号、购买靓号 | 转移、赠送、操作记录 |
| **定位** | "获取与绑定" | "管理与处置" |

> 短号的领取和购买入口不变，仍在 App 身份管理页的账号卡片下。短号中心专注于资产的流转与处置。

## 3. 短号资产模型

### 3.1 资产化升级

短号采用类似 NFT 的所有权模型：

```js
ShortNumberAsset = {
    number: "9573326140",         // 短号号码
    type: "free" | "premium",     // 类型：免费号 / 靓号
    network: "OBChain",           // 所属网络
    ownerAddress: "0x71C7...898A5",  // 当前所有者地址
    status: "bound" | "transferring" | "listed",
    //   bound: 已绑定（默认状态）
    //   transferring: 转移进行中（链上交易广播中）
    //   listed: 已挂售（未来扩展）
    acquiredAt: "2026-07-10",
    acquisitionMethod: "free_claim" | "purchase" | "transfer_in" | "gift_in",
    premiumType: "豹子" | "顺子" | "四连同" | "三连+对" | "双对子" | "吉尾号" | "普通号",
    // 流转记录（链上可查）
    transferHistory: [
        { from: "0x...", to: "0x...", type: "transfer" | "gift", txHash: "0x...", timestamp: "..." }
    ]
}
```

### 3.2 状态机

```
            [领取/购买]
                │
                ▼
           ┌─────────┐    [发起转移/赠送]   ┌──────────────┐
           │  bound  │ ──────────────────→ │transferring │
           │ (已绑定) │                      │ (转移进行中) │
           └─────────┘                      └──────┬───────┘
                ↑                                  │
                │                           [链上确认]
                │                                  │
                │                                  ▼
                │                           ┌─────────┐
                └───────────────────────────│  bound  │
                                            │(绑定新主)│
                                            └─────────┘
                ← 未来扩展 →
                [挂售上架] → listed → [取消挂售] → bound
                             listed → [被购买] → bound(新主)
                [定向转卖] → transferring → bound(新主)
```

### 3.3 所有权规则

| 规则 | 说明 |
|------|------|
| 链上确权 | 短号所有权由智能合约记录，本地仅做镜像展示 |
| 一号一主 | 每个短号在同一网络下只有一个当前所有者地址 |
| 转移即换主 | 转移/赠送后，原地址失去该短号 |
| 跨网络不可转移 | A 网络的短号不能转移到 B 网络 |
| 免费号可转移 | 免费号领取后同样可以转移/赠送 |
| 靓号可转移 | 靓号购买后同样可以转移/赠送 |

### 4.2 转移功能

**定义**：将自己的短号从一个钱包地址转移到自己名下的另一个钱包地址。

**入口**：资产卡片 →「转移」

```
┌──────────────────────────────────────────────┐
│  转移短号                                ✕   │
├──────────────────────────────────────────────┤
│                                              │
│  💎 21008 · 豹子 ×50 · OBChain               │  短号信息
│  当前所有者：自管钱包A 0x71C7...898A5         │
│                                              │
│  转入钱包                                     │
│  ┌──────────────────────────────────────┐    │
│  │ ○ 自管钱包B (Ethereum)                │    │  单选列表
│  │   0x3a5b...8d1a2                     │    │  (排除当前地址
│  │ ○ 自管钱包C (Arbitrum)                │    │   和不同网络的)
│  │   0x8c2d...4e7f1                     │    │
│  └──────────────────────────────────────┘    │
│                                              │
│  ⚠️ 转移后原地址将不再持有此短号              │
│                                              │
│  🔒 PIN 码 [__________]                      │
│                                              │
│  [    取消    ] [   确认转移   ]             │

└──────────────────────────────────────────────┘
```

**转移流程**：点击转移 → 选择转入钱包（仅自己的同网络地址）→ 输入 PIN → 链上签名 → 确认成功 → 刷新列表

**转移规则**：

| 规则 | 说明 |
|------|------|
| 仅限自己的地址 | 转入钱包从本地冷钱包列表选择 |
| 排除当前地址 | 自动排除短号当前持有地址 |
| 同网络 | 只能转移到同网络的地址 |
| 免费号可转 | 免费号转移后，新地址的免费号额度视为已使用 |
| PIN 签名 | 当前持有地址的私钥签名 |

**赠送流程**：点击赠送 → 输入/扫码对方地址 → 输入 PIN → 链上签名 → 确认成功 → 短号从列表移除

**赠送规则**：

| 规则 | 说明 |
|------|------|
| 任意地址 | 接收方为任意有效钱包地址 |
| 地址校验 | 输入地址需通过格式校验（0x + 40位十六进制） |
| 扫码 | 支持扫描对方钱包二维码填入地址 |
| 不可撤回 | 链上确认后无法撤回 |
| PIN 签名 | 当前持有地址的私钥签名 |
| 赠送后移除 | 成功后该短号从本机资产列表移除 |

### 5.2 智能合约接口预留

本期实现基础流转，预留交易接口：

```solidity
interface IShortNumberAsset {
    
    // 基础查询
    function ownerOf(string memory number, string memory network) 
        external view returns (address);
    
    // 第一层：基础流转（本期）
    function transfer(string memory number, string memory network, address to) external;
    function gift(string memory number, string memory network, address to) external;
    
    // 第二层：定向转卖（预留）
    function sellToBuyer(string memory number, string memory network, address buyer, uint256 price) external;
    function acceptSale(string memory number, string memory network) external payable;
    function cancelSale(string memory number, string memory network) external;
    
    // 第三层：市场挂售（预留）
    function listForSale(string memory number, string memory network, uint256 price) external;
    function buyFromListing(string memory number, string memory network) external payable;
    function cancelListing(string memory number, string memory network) external;
    
    // 事件
    event Transfer(string number, string network, address from, address to);
    event Gift(string number, string network, address from, address to);
    event SaleListed(string number, string network, address seller, uint256 price);
    event SaleCompleted(string number, string network, address seller, address buyer, uint256 price);
    event SaleCancelled(string number, string network, address seller);
}
```

## 6. 核心业务规则

### 6.1 免费号额度规则（转移/赠送场景）

| 场景 | 规则 |
|------|------|
| 转出免费号 | 原地址的免费号额度不释放（已领记录永久保留） |
| 转入免费号 | 新地址的免费号额度视为已使用（不能再领免费号） |
| 赠出免费号 | 同转出规则 |
| 收赠免费号 | 同转入规则 |

> 防止用户通过"领取→转移→再领取"循环刷免费号。

### 6.2 与现有模块的关系

| 维度 | App 身份管理页 | 短号中心 |
|------|-------------|---------|
| 数据来源 | 同一条链上数据 | 同一条链上数据 |
| 视角 | 按账号维度 | 按资产维度 |
| 操作 | 领取/购买 | 转移/赠送 |
| 刷新联动 | 转移后两边同步刷新 | 转移后两边同步刷新 |

### 6.3 Gas 费

* 转移/赠送的 Gas 由短号当前所有者地址支付
* Gas 从该地址的 RC Token 余额扣除
* 交易前检查余额，不足时提示

## 8. 风险与注意事项

| 风险 | 说明 | 应对 |
|------|------|------|
| 赠错地址 | 赠送时输入错误地址，短号无法找回 | 地址输入二次确认 + 格式校验 |
| Gas 不足 | 持有地址余额不足以支付 Gas | 交易前检查余额，不足时提示 |
| 链上延迟 | 交易确认需要时间 | transferring 状态锁定按钮，展示进度 |
| 免费号刷量 | 通过转移循环刷免费号 | 额度永久绑定地址，转移后不释放 |
| 并发操作 | 同一短号被同时发起转移和赠送 | 链上合约防双花，本地先到先得锁定 |
