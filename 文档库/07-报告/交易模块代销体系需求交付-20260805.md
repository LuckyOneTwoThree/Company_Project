---

## 一、背景

v1.0 版本基线已定版(详见《功能定版清单-2026-07-31》),商城为"官方统一商品池 + 级差返利"模型,所有用户看同一商品池、同一价格。

本次在此基础上新增**代理代销能力**,解决两个问题:
1. 商品缺少规格属性(如手机 8+128 / 12+256),无法满足真实零售场景
2. 缺少代理批发-零售链路,代理无法自主定价卖给下级

---

## 二、核心交付内容(5 项功能)

| #   | 功能              | 说明                                        |
| --- | --------------- | ----------------------------------------- |
| 1   | **商品 SKU 规格属性** | 商品支持多规格选择(参考京东淘宝),影响价格的属性独立成 SKU,独立定价独立库存 |
| 2   | **代销资格准入**      | 购买特定商品获得代销资格,无资格者不能代销;任意层级均可获得            |
| 3   | **代销进货(买断式)**   | 代理按官方代销进货价批量买断商品,获得 SN 后自主定价代销            |
| 4   | **代销管理**        | 整合到"我的持有",按 SKU 聚合展示,支持调价/上下架             |
| 5   | **下级购买代销商品**    | 下级看全量商品池,但仅能购买上级有代销库存的 SKU,无货提示联系上级       |

---

## 三、业务价值

1. **激活代理能动性**:代理可自主定价、赚差价,从"被动分润"变"主动经营"
2. **补齐零售能力**:SKU 规格属性补齐,商城可承接真实零售商品(如手机、硬件设备)
3. **层级自运转**:任意层级有资格者均可代销,形成多层分销网络,不依赖官方直营
4. **买断式风险可控**:代理先进货再代销,官方不承担库存风险,与寄售模式相比资金流更健康

## 五、关键设计决策

| 决策点 | 方案 | 理由 |
|---|---|---|
| 代销模式 | 买断式(非寄售) | 代理先花钱进货,官方不承担库存风险 |
| 定价粒度 | 按 SKU 独立定价 | 不同规格成本不同,需独立定价 |
| 资格准入 | 购买特定商品解锁 | 复用现有代理能力商品机制,门槛过滤 |
| 管理入口 | 整合到"我的持有" | 代销的 SN 本就是代理持有资产,避免入口割裂 |
| 商品池可见性 | 全量可见,按 SKU 判断购买 | 下级能看全量商品,但只能买上级代销的,无货引导联系上级 |
| 代销层级 | 任意层级,仅对直接下级可见 | 激励各级自己进货,避免无限传递 |

## 六、待定事项(后续决策)

| # | 事项 | 说明 |

| 3 | 合约改造 | 部分功能现有合约不兼容,需后续技术评估与改造 |

---

## 七、风险提示

1. **合约改造量大**:商品 SKU 规格层、代销体系均为合约层新增,需排期开发,原型阶段以需求为主
2. **与已废弃 v2.0 的区别**:本次代销为"买断式+任意层级+资格准入",与 2026-07-25 废弃的 v2.0"层级化代销"本质不同,需避免概念混淆
3. **代销分润未定**:分润机制影响代理动力与平台收入,需尽快决策

---

**结论**:周三交付原型 + 方案文档,届时可直观看到代销商城全流程。代销分润机制与合约改造排期待业务方向进一步明确后推进。
