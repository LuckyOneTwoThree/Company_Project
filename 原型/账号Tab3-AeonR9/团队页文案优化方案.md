# 团队页 / 返佣文案优化方案（node_tab3_demo_v2.html）

> 目标：消除用户端展示歧义，重点解决「L」系列命名冲突；统一收益类词汇口径；清除 C 端技术术语泄漏；软化敏感措辞。
> 范围：手机屏内（C 端可见）文案。右侧「仿真操作面板 / 两层准入说明」是内部演示用，保留技术词不改。

---

## 一、核心问题：一个「L」背了四套概念

| 概念 | 当前写法 | 出现位置（示例行号） | 用户读到时会以为 |
|---|---|---|---|
| ① 用户/代理等级（rank 1–10） | `L3`、`申请 L4`、`L1-L2 用`、`L3+ 用` | 2563、2589、2600、2646-2649、2748、2753 | —（基准概念） |
| ② 返佣层级（layer 1–3，代际深度） | `L1层 / L2层 / L3层`、`下级购买您拿 L1 层` | 2524、2670-2671、2686、2783、佣金记录徽章 800-803 | ❌ 误以为是「L1 等级的人给我返佣」 |
| ③ 上级链路深度 | `LX 上上级 / LY 直接上级`、链路格式 `LX.LY` | 244、444-458、1806 | ❌ 以为是某种等级或神秘编号 |
| ④ 未达代理等级 | `未达到代理等级（L0）` | 2797、4305 | ❌ L0 从未在等级表中出现，凭空概念 |

**最致命的一句**（2686 行）：
> 「下级购买您拿 L1 层；下级的下级购买您拿 L2 层」

用户自己就是 L3 等级，读到「拿 L1 层」100% 会混淆成等级。返佣比例表表头更是三种口径混排：`等级 | 直接下级 | L2层 | L3层`——第一列是等级 L1-L10，第二列是描述语，三四列又是层级 L。

## 二、命名方案

### 推荐方案 A：等级用「Lv.」，层级用「代」

| 概念 | 新命名 | 示例 |
|---|---|---|
| 用户等级 | **Lv.1 ~ Lv.10** | 「代理等级 Lv.3」「申请升级 Lv.4」 |
| 返佣层级 | **第1代 / 第2代 / 第3代**（直接邀请的好友 = 第1代） | 表头「1代（直邀）/ 2代 / 3代」 |
| 上级链路 | 直接用中文：**上级 / 上上级** | 「上级 #100028 · 张三」 |
| 未达等级 | 「**未达到 Lv.1**」 | 不再出现 L0 |

理由：
- 「Lv.」是游戏/会员体系通用等级符号，用户零学习成本，且与合约 rank 数字一一对应；
- 「代」天然表达代际关系（我→1代→2代），不与「级/层/等级」冲突，微信读书、拼多多等分销体系均用「一度/直邀好友」类表达；
- 上级链路本来只展示两级，没必要造 LX/LY 字母代号，中文直接说清。

### 备选方案 B：等级用 V1–V10
缺点：原型里已有「VIP 会员订阅」商品，V 系会和 VIP 撞车，不推荐。

### 备选方案 C：层级用「一级/二级/三级好友」
缺点：「级」与等级仍然同字，读快了照样混，不推荐。

## 四、收益类词汇统一（现状 5 个词混用）

现状：**返佣 / 佣金 / 分成 / 提成 / 收益** 交替出现，同一页面「返佣领取→已领佣金明细→收益合约→提取记录」四连跳。

统一规则：
- **功能名词一律「佣金」**：可领佣金、领取佣金、佣金中心、佣金合约、领取记录；
- **「返佣」只用于描述机制**的句子里（如「返佣规则」「自动返佣」）；
- **弃用**：提成、分成（数据源 source 字段一并改）；
- **动词一律「领取」**，弃用「提取」「划转提现」（claim 的唯一译法）。

## 五、口径与一致性问题

### 5.1 「团队人数」口径必须钉死（数据层待确认 ⚠）
- 主页卡「50人」= l1Count 12 + l2Count 38，但 38 到底是「仅第2代」还是「第2+3代」原型未定义；
- 而团队积分 `teamDepth=10`（上溯10层）、返佣只有 3 代——**同一个"团队"三种深度**。
- 建议：主页与团队页的人数统一按「返佣可及范围 = 3 代」统计并标注「含3代」；团队积分处单独注明「按全团队（10层）累计」。**此项需与合约同学确认统计口径后再定稿。**

### 5.2 冗余数据清理
- `commissionRecords`（800-803）注释写「保留用于历史兼容」，若已无页面引用，建议删除，避免后续开发照抄里面的 L1/L2/L3 徽章写法。

## 六、敏感措辞软化（合规建议）

| 现文案 | 风险 | 建议 |
|---|---|---|
| `裂变团队` | 传销联想词，应用商店审核敏感 | `间接成员` |
| `直推` | 微商术语 | `直邀`（全文统一） |
| `下级 / 下级的下级` | 层级从属感强 | 规则文案改用「您邀请的好友 / 好友的好友」「团队成员」 |
| `上下级关系终身锁定，不可撤销` | 表述过硬，易引发客诉 | `邀请关系上链后不可变更，请确认后绑定`（右侧面板可保留原文） |
| `这激励大家都积极升级` | 诱导性表述 | 删除该句 |

> 注：三级返佣 + 团队积分升级本身即有传销认定风险（层级计酬），文案软化不改变机制性质，建议产品侧另行合规评估。

## 七、实施注意（改代码前必读）

1. **文件内有两套几乎相同的渲染代码**：`renderSubpage` 在 3639 行被二次定义（注释：“由原文件尾部错位内容收回并并入”），JS 后者覆盖前者——`team / commission / upgrade / level-system` 等页面**实际生效的是后一份**。改文案必须两份同步改（或借机删掉失效的前一份 + `.bak` 文件，消除隐患）。
2. 右侧「🔒 两层准入说明 / ⚙️ 仿真操作面板」为内部演示区，`addReward`、`EIP-712`、`RewardClaim` 等技术词**保留不改**。
3. 层级标签是拼接生成的（`'L' + (idx+1) + '层'`，2524 行等处），改模板字符串即可全局生效。
4. `commission_detail_demo.html` 经检查无 L 系冲突，暂不动。
